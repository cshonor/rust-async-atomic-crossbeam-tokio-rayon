## 1. 无锁的目标

**不依赖线程在内核里睡眠等待锁**；多线程靠**原子操作**协作，并保证系统**至少有一个线程总能推进**（lock-free 进展性；更强还有 wait-free）。

与第 9 章对比：

| | 第 9 章 | 第 10 章 |
|---|---------|----------|
| 范式 | **悲观**：先拿锁，冲突则 wait | **乐观**：先改，提交时 CAS，失败重试 |
| 阻塞 | futex / `atomic_wait` | 用户态 CAS，无 syscall（理想路径） |

## 2. 两大设计基石

### 2.1 原子指针与「增加间接性」

- 硬件擅长原子地改 **指针 / 整数**，不能直接原子地改整个大结构。  
- 数据放堆上，用 **`AtomicPtr<T>`** 表示「当前版本」；整体替换 = 改指针。

### 2.2 RCU（Read-Copy-Update）

1. **Read**：`load` 得到当前只读视图（指针）。  
2. **Copy**：在私有副本上修改。  
3. **Update**：`compare_exchange` 仅当全局指针仍指向**读到的旧版本**时，换成新版本；失败则重试。

与第 2 章 CAS、[CAS与Fetch-Modify专题.md](../Chapter-02-Atomics/CAS与Fetch-Modify专题.md) 直接相关。

## 3. 无锁链表（Stack 入栈）思路

```text
Node { data, next: AtomicPtr<Node> }
head: AtomicPtr<Node>
```

**Push（入栈）** — 经典 CAS 循环：

1. `new_node` 分配节点。  
2. `current_head = head.load(Relaxed)`。  
3. `new_node.next = current_head`。  
4. `head.compare_exchange_weak(current_head, new_ptr, Release, Relaxed)`。  
5. 失败则更新 `current_head`，回到 3。

**难点**：**中间删除**、多消费者出栈 — 前置指针与并发 insert 交织会「丢节点」；需更复杂算法（书中启发，非一行 CAS 能搞定）。

## 4. 难点：安全边界与内存回收

| 难点 | 说明 |
|------|------|
| **并发结构冲突** | 删节点时其他线程仍在该节点后插入 → 逻辑损坏 |
| **回收时机** | CAS 摘掉节点后**不能立刻 `drop`** — 读者可能仍持有旧指针 → **UAF / UB** |
| **ABA** | 指针 A→B→A；CAS 以为未变而成功，实际逻辑已乱 |

### 回收策略（生态常见）

| 策略 | 特点 |
|------|------|
| **泄漏** | 最安全兜底，不适合长期运行 |
| **原子引用计数** | 侵入结构，开销大 |
| **Hazard Pointers** | 读者登记「正在用的指针」，推迟释放 |
| **Epoch / QSBR** | **crossbeam-epoch** 思路：静默期后批量回收 |

仓库 **`atomic/crossbeam/`** 为 channel 示例；生产无锁队列见 **`crossbeam-queue`**、`dashmap` 等 crate，**勿轻易徒手造轮子**。

## 5. 性能：优势与风险

### 优势

- **无 syscall**（成功路径）：用户态原子指令，延迟低。  
- **抗优先级反转**：高优先级线程不必等低优先级「持锁睡眠」。  
- **Sequence Lock** 等：写者不堵读者、读者几乎只读 — 内核时间戳等读多写少极致场景。

### 风险

- **CAS 风暴**：极高写竞争时全员自旋重试，CPU 打满，**可能不如 Mutex**。  
- **缓存行争用**：多线程抢同一 `AtomicPtr` 所在 cache line → **false sharing**（见第 7 章、[互斥锁与锁体系-贯通笔记.md](../互斥锁与锁体系-贯通笔记.md) §5.4）。

## 6. 有锁 vs 无锁选型（表）

| 维度 | 有锁 Mutex / RwLock | 无锁 Lock-Free / RCU / SeqLock |
|------|---------------------|--------------------------------|
| 思想 | 悲观：冲突则睡眠 | 乐观：CAS 提交 |
| 场景 | **通用**、写多、临界区长、可接受阻塞 | **读多写少、极低延迟**、内核/交易/驱动 |
| Rust 难度 | 类型系统兜底，**日常首选** | **`unsafe` + 回收 + ABA**，基础设施级 |
| 建议 | 第 9 章混合锁（自旋再 futex） | **`crossbeam-queue`** 等成熟库 |

## 8. 面试一句话

**无锁靠 AtomicPtr 与 CAS 乐观提交；RCU 读-拷-换；链表入栈易删难；回收用 epoch/hazard 防 UAF；ABA 要防；高竞争 CAS 可能不如 Mutex；Rust 日常用 Mutex，无锁用成熟库。**
