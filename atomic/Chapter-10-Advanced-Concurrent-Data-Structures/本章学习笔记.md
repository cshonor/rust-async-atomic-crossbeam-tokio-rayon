## 1. 第十章核心：进阶并发设计模式

第十章将原子操作、内存序与 OS 原语**组合**成内核与高性能场景常见的结构；下列模式可互相当「积木」。

### 1.1 信号量（Semaphore）

- 带**计数器**的同步原语：`wait` / `P`（减一，不足则阻塞）、`signal` / `V`（加一，可能唤醒等待者）。  
- 保证计数**不为负**（实现细节因 API 而异）。  
- **二元信号量**（最大值 1）可用来实现 **Mutex** 或配合条件变量语义。  
- 与第 8 章 futex、第 9 章三态锁的关系：锁常是「0/1/2 状态机 + wait/wake」，信号量是更一般的「资源配额」抽象。

### 1.2 RCU（Read-Copy-Update）

专为**读多写少**设计的无锁（或近乎无锁）模式，Linux 内核大量使用：

1. **Read**：原子 `load` 指针，只读访问当前版本。  
2. **Copy**：在**私有副本**上修改。  
3. **Update**：`compare_exchange` 仅当全局指针仍指向读到的旧版本时替换；失败重试。  
4. **回收**：等所有仍持有旧指针的读者结束后，再释放旧内存（epoch / hazard pointers / 延迟队列）。

与 [CAS与Fetch-Modify专题.md](../Chapter-02-Atomics/CAS与Fetch-Modify专题.md)、§2 无锁基石一致。

### 1.3 无锁链表（Lock-Free Linked List）

- 节点：`next: AtomicPtr<Node>`；表头：`head: AtomicPtr<Node>`。  
- **头部 Push** 用 CAS 循环即可（见 §2.3）。  
- **工程噩梦**：中间删除 + **内存回收** — 不能 CAS 摘掉就立刻 `drop`；需 **Hazard Pointers** 或 **Quiescent State Tracking（QSBR / epoch）**。  
- **ABA**：指针 A→B→A 骗过 CAS → 悬垂指针或丢节点。

### 1.4 Parking Lot（基于队列的紧凑锁）

- 把**等待线程队列**放到**全局哈希表**（Parking lot），锁对象本身只占极少位（甚至塞进指针未使用位）。  
- 效果：**细粒度、近零额外空间**的 Mutex 实现思路（`parking_lot` crate 工业实现）。  
- 与第 8 章 `futex`、第 9 章「无竞争路径零 syscall」同一条优化线。

### 1.5 顺序锁（Sequence Lock / SeqLock）

- 原子**序列号** `seq` 协调读写：  
  - **写者**：修改前 `seq += 1`（变**奇数**表示写入中）→ 写数据 → 再 `seq += 1`（变**偶数**表示稳定）。  
  - **读者**：读 `seq₁` → 读数据 → 读 `seq₂`；若 `seq₁ == seq₂` 且为**偶数**，则期间无并发写。  
- 写者不必等读者；读者几乎无原子写，**读吞吐极高** — 内核时间戳、读极多写极少配置。  
- 读者可能需**重试**（写入期间读到不一致快照）。

## 2. 无锁编程：目标、基石与选型

### 2.1 目标与第 9 章对比

| | 第 9 章 | 第 10 章（无锁） |
|---|---------|------------------|
| 范式 | **悲观**：先拿锁，冲突则 wait | **乐观**：先改，CAS 提交，失败重试 |
| 阻塞 | futex / `atomic_wait` | 理想路径仅用户态原子指令 |
| 进展性 | 阻塞锁 | **Lock-free**：至少一线程总能推进 |

### 2.2 基石：AtomicPtr 与 RCU

- **间接性**：复杂数据在堆上，用 **`AtomicPtr<T>`** 原子替换「当前版本」。  
- **RCU**：Read → Copy → CAS Update（§1.2）。

### 2.3 无锁栈 Push（CAS 循环）

```text
Node { data, next: AtomicPtr<Node> }
head: AtomicPtr<Node>
```

1. 分配 `new_node`，`next = current_head`。  
2. `head.compare_exchange_weak(current_head, new_ptr, Release, Relaxed)`。  
3. 失败则更新 `current_head` 重试。

### 2.4 回收、ABA、性能权衡

| 难点 | 要点 |
|------|------|
| 删除/插入交织 | 中间删节点易与并发 insert 冲突 |
| 回收 | 摘掉节点后**不能立刻 drop** |
| ABA | A→B→A 误导 CAS |
| CAS 风暴 | 极高写竞争时自旋可能**不如 Mutex** |
| False sharing | 多线程抢同一 cache line（第 7 章、[互斥锁与锁体系-贯通笔记.md](../互斥锁与锁体系-贯通笔记.md) §5.4） |

| 回收策略 | 特点 |
|----------|------|
| 泄漏 | 安全兜底 |
| 原子引用计数 | 侵入、开销大 |
| Hazard Pointers | 读者登记在用指针 |
| Epoch / QSBR | crossbeam-epoch 类库 |

| 维度 | 有锁 | 无锁 / RCU / SeqLock |
|------|------|----------------------|
| 场景 | 通用、写多、临界区长 | 读多写少、极低延迟、内核/交易 |
| Rust | **日常首选** `std::sync` | **`unsafe`**；用 **crossbeam-queue**、**dashmap** 等 |

## 3. 高并发 Rust 程序整体设计思路（全书自顶向下）

1. **类型系统与安全先行**  
   - 所有权 + 借用：**编译期**消除大部分数据竞争。  
   - 明确 **`Send`**（所有权可跨线程转移）与 **`Sync`**（`&T` 可跨线程共享，即 `&T: Send`）。  
   - 含裸指针等不安全资源时，用 **`PhantomData`** 取消错误的自动 `Send`/`Sync`。

2. **状态机 + 原子 + OS 原语**  
   - 将并发抽象为少量状态（如 Mutex：`0` 未锁 / `1` 已锁无等待 / `2` 已锁有等待）。  
   - `AtomicU32` + **futex** / `WaitOnAddress`：无竞争走用户态，有竞争再陷入内核（第 8～9 章）。

3. **读写分离与争用局部化**  
   - 读多写少：**`RwLock`**，注意**写者饥饿**（第 9 章写优先状态机、[RwLock与读写锁体系-贯通笔记.md](../RwLock与读写锁体系-贯通笔记.md)）。  
   - 极端读性能：**RCU**、**SeqLock**（§1.2、§1.5）。

## 4. 性能优化方向与最佳实践

| 方向 | 做法 |
|------|------|
| **避免伪共享** | 缓存行通常 **64B**；多线程改同一行内不同原子变量会打爆一致性流量。用 **`#[repr(align(64))]`** 隔离高频原子变量。 |
| **减少 syscall** | 解锁时若**无人等待**，不要无谓 `wake`（第 9 章状态机）。 |
| **混合锁** | 阻塞前先 **`spin_loop()`** 自旋 N 次（如 ~100），持锁方若在另一核快速释放可避免上下文切换（第 4、9 章）。 |
| **CAS 循环用 `weak`** | ARM 等 LL/SC 可能**虚假失败**；`loop` 内优先 **`compare_exchange_weak`**（[CAS与Fetch-Modify专题.md](../Chapter-02-Atomics/CAS与Fetch-Modify专题.md)）。 |
| **降低内存序** | 勿滥用 **`SeqCst`**；计数器用 **`Relaxed`**；锁与消息传递用 **`Acquire`/`Release`**（[Chapter-03](../Chapter-03-Memory-Ordering/)、[Atomics与内存序-贯通笔记.md](../Atomics与内存序-贯通笔记.md)）。 |

## 5. 调试排错与并发陷阱

| 手段 / 陷阱 | 说明 |
|-------------|------|
| **Miri** | 在 MIR 层跑测试，抓 UB、非法指针、**数据竞争**（`cargo +nightly miri test`）。 |
| **虚假唤醒** | `park` / `Condvar::wait` 可能无通知而醒来 → **永远在 `while !cond { wait }` 里**，勿用单次 `if`（[Condvar与条件变量-贯通笔记.md](../Condvar与条件变量-贯通笔记.md)、`use_condvar.rs`）。 |
| **死锁 / 锁中毒** | 临界区要短，避免持锁 I/O；`lock().unwrap()` 在持锁线程 panic 后得 **PoisonError**（防读不一致数据）。 |
| **`if let` 锁作用域** | `if let Some(x) = mutex.lock().unwrap().pop()` 会在**整个 `if` 块**持锁 → 先 `let mut g = lock()`，用完 **`drop(g)`** 再干别的。 |

## 6. 面试核心考点（全书浓缩）

### 6.1 `Send` 与 `Sync`

| 类型 | Send | Sync | 记忆 |
|------|------|------|------|
| `Rc` | ✗ | ✗ | 非线程安全引用计数 |
| `Cell` | ✓ | ✗ | 单线程内部可变性 |
| `RefCell` | ✓ | ✗ | 运行时借用 |
| `Arc<T>` | T 决定 | T 决定 | `T: Send + Sync` 时通常两者皆可 |

- **Send**：所有权可安全移到另一线程。  
- **Sync**：`&T` 可安全跨线程共享 ⇔ **`&T: Send`**。

### 6.2 内部可变性（Interior Mutability）

- 默认不能通过 `&T` 修改；**`UnsafeCell`** 是底层逃生舱。  
- 单线程：`Cell`、`RefCell`；多线程：`Atomic*`、`Mutex`、`RwLock`。

### 6.3 Rust `Mutex<T>` vs C/C++ Mutex

- C/C++：锁与数据**分离**，靠纪律「先锁后访问」。  
- Rust：**`Mutex` 包裹数据** + **`MutexGuard` RAII**，编译期强制「持锁才能访问」。

### 6.4 Happens-Before 与 Release-Acquire

- 线程 A **Release** 写（放锁、发信号），线程 B **Acquire** 读且读到 A 的值 → 建立 **Happens-Before**。  
- A 在 Release **之前**的所有写，对 B 在 Acquire **之后**的读**可见**；防 CPU/编译器重排导致脏读。

### 6.5 CAS 与 ABA

- **CAS**：若当前值 == 期望，则原子替换；无锁基础。  
- **ABA**：A→B→A，CAS 误以为未变 → 无锁指针结构致命。

### 6.6 `compare_exchange` vs `compare_exchange_weak`

- **weak** 允许**虚假失败**（值已相等仍失败），适合包在 **`loop`** 里重试；RISC 上常更省指令。
