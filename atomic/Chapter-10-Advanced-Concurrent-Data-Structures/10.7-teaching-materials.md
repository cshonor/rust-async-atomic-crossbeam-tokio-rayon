## 4. 性能优化方向与最佳实践

| 方向 | 做法 |
|------|------|
| **避免伪共享** | 缓存行通常 **64B**；多线程改同一行内不同原子变量会打爆一致性流量。用 **`#[repr(align(64))]`** 隔离高频原子变量。 |
| **减少 syscall** | 解锁时若**无人等待**，不要无谓 `wake`（第 9 章状态机）。 |
| **混合锁** | 阻塞前先 **`spin_loop()`** 自旋 N 次（如 ~100），持锁方若在另一核快速释放可避免上下文切换（第 4、9 章）。 |
| **CAS 循环用 `weak`** | ARM 等 LL/SC 可能**虚假失败**；`loop` 内优先 **`compare_exchange_weak`**（[CAS与Fetch-Modify专题.md](../Chapter-02-Atomics/CAS与Fetch-Modify专题.md)）。 |
| **降低内存序** | 勿滥用 **`SeqCst`**；计数器用 **`Relaxed`**；锁与消息传递用 **`Acquire`/`Release`**（[Chapter-03](../Chapter-03-Memory-Ordering/)、[Atomics与内存序-贯通笔记.md](../Atomics与内存序-贯通笔记.md)）。 |

## 5. 调试排错与并发陷阱

| 手段 / 陷阱 | 说明 |
|-------------|------|
| **Miri** | 在 MIR 层跑测试，抓 UB、非法指针、**数据竞争**（`cargo +nightly miri test`）。 |
| **虚假唤醒** | `park` / `Condvar::wait` 可能无通知而醒来 → **永远在 `while !cond { wait }` 里**，勿用单次 `if`（[Condvar与条件变量-贯通笔记.md](../Condvar与条件变量-贯通笔记.md)、`../Chapter-01-Rust-Concurrency-Basics/1.8-parking-condvar/1.8-parking-condvar-demo.rs`）。 |
| **死锁 / 锁中毒** | 临界区要短，避免持锁 I/O；`lock().unwrap()` 在持锁线程 panic 后得 **PoisonError**（防读不一致数据）。 |
| **`if let` 锁作用域** | `if let Some(x) = mutex.lock().unwrap().pop()` 会在**整个 `if` 块**持锁 → 先 `let mut g = lock()`，用完 **`drop(g)`** 再干别的。 |

## 6. 面试核心考点（全书浓缩）

### 6.1 `Send` 与 `Sync`

| 类型 | Send | Sync | 记忆 |
|------|------|------|------|
| `Rc` | ✗ | ✗ | 非线程安全引用计数 |
| `Cell` | ✓ | ✗ | 单线程内部可变性 |
| `RefCell` | ✓ | ✗ | 运行时借用 |
| `Arc<T>` | T 决定 | T 决定 | `T: Send + Sync` 时通常两者皆可 |

- **Send**：所有权可安全移到另一线程。  
- **Sync**：`&T` 可安全跨线程共享 ⇔ **`&T: Send`**。

### 6.2 内部可变性（Interior Mutability）

- 默认不能通过 `&T` 修改；**`UnsafeCell`** 是底层逃生舱。  
- 单线程：`Cell`、`RefCell`；多线程：`Atomic*`、`Mutex`、`RwLock`。

### 6.3 Rust `Mutex<T>` vs C/C++ Mutex

- C/C++：锁与数据**分离**，靠纪律「先锁后访问」。  
- Rust：**`Mutex` 包裹数据** + **`MutexGuard` RAII**，编译期强制「持锁才能访问」。

### 6.4 Happens-Before 与 Release-Acquire

- 线程 A **Release** 写（放锁、发信号），线程 B **Acquire** 读且读到 A 的值 → 建立 **Happens-Before**。  
- A 在 Release **之前**的所有写，对 B 在 Acquire **之后**的读**可见**；防 CPU/编译器重排导致脏读。

### 6.5 CAS 与 ABA

- **CAS**：若当前值 == 期望，则原子替换；无锁基础。  
- **ABA**：A→B→A，CAS 误以为未变 → 无锁指针结构致命。

### 6.6 `compare_exchange` vs `compare_exchange_weak`

- **weak** 允许**虚假失败**（值已相等仍失败），适合包在 **`loop`** 里重试；RISC 上常更省指令。
