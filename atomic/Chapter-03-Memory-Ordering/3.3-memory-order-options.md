### ② `Release`（释放）与 ③ `Acquire`（获取）

**必须成对** — 并发通信的「工作马」。

| | Release | Acquire |
|---|---------|---------|
| **用于** | **Store**（及 RMW 的写侧） | **Load**（及 RMW 的读侧） |
| **屏障** | 前面的内存操作**不能**排到它**之后** | 后面的内存操作**不能**排到它**之前** |
| **HB** | A：`Release` store → B：`Acquire` load **读到该写入** → A 在 Release **之前**的写对 B 在 Acquire **之后**可见 |

**场景**：消息传递、**互斥锁 / 自旋锁**（先写数据，再 Release 标志；读标志用 Acquire，再读数据）。

→ 代码：``../Chapter-02-Atomics/2.1-atomic-load-store/2.1-atomic-load-store-demo.rs``；**第 4 章**：[4.1-minimal-implementation/4.1-minimal-implementation-demo.rs](../Chapter-04-Spin-Locks/4.1-minimal-implementation/4.1-minimal-implementation-demo.rs)

### ④ `Ordering::AcqRel`（获取并释放）

| 项 | 内容 |
|----|------|
| **用于** | **RMW**（`fetch_add`、`compare_exchange`、`swap` 等） |
| **语义** | 读侧 **Acquire** + 写侧 **Release** 合一 |
| **场景** | 单次原子操作既要「看见之前发布」又要「向后续发布」 |

### ⑤ `Ordering::SeqCst`（顺序一致）

| 项 | 内容 |
|----|------|
| **保证** | 含 Acquire/Release 约束 + 所有 **SeqCst** 操作共有一条 **全局严格总顺序** |
| **效果** | 所有线程对 SeqCst 操作看到**同一条时间线** |
| **场景** | **极少** — 如书中「双旗帜」：线程需根据**两个不同原子**写入的**全局先后**做决策 |
| **审查** | 代码里大量 SeqCst 常是**警告信号**（未分析清需求或偷懒） |

### 对照表（必背）

| Ordering | 跨线程 HB | 典型 |
|----------|-----------|------|
| Relaxed | 无 | 独立计数 |
| Release | 与配对 Acquire | 发布 / 解锁 |
| Acquire | 读到 Release 后 | 订阅 / 加锁 |
| AcqRel | RMW 双向 | fetch/CAS/swap 当信使 |
| SeqCst | 全局 SeqCst 顺序 | 多原子全局先后决策 |
