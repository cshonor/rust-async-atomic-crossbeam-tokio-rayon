## 3.3 Memory Order Options（内存序选项）

> 书 §3.3 · 前：[3.2 内存模型](./3.2-the-memory-model.md) · 索引：[本章学习笔记.md](./本章学习笔记.md) · 后：[3.4 Fences](./3.4-fences.md) · Demo：[3.3-memory-order-options-demo.rs](./3.3-memory-order-options/3.3-memory-order-options-demo.rs)

---

Rust 提供五种 **`std::sync::atomic::Ordering`**。每次 `load` / `store` / `fetch_*` / `compare_exchange` **都必须显式传入**。

---

## ① `Ordering::Relaxed`（宽松）

| 项 | 内容 |
|----|------|
| **保证** | **无**跨线程 HB；仅同一原子变量的 **总修改顺序（Total Modification Order）** |
| **效果** | 可与其它内存操作重排；他线程可能先看到原子更新，仍看不到此前对普通内存的写 |
| **场景** | 独立计数器、唯一 ID、与「别内存就绪」无关的统计 |

---

## ② `Release`（释放）与 ③ `Acquire`（获取）

**必须成对** — 并发通信的「工作马」。

| | Release | Acquire |
|---|---------|---------|
| **用于** | **Store**（及 RMW 的写侧） | **Load**（及 RMW 的读侧） |
| **屏障** | 前面的内存操作**不能**排到它**之后** | 后面的内存操作**不能**排到它**之前** |
| **HB** | A：`Release` store → B：`Acquire` load **读到该写入** → A 在 Release **之前**的写对 B 在 Acquire **之后**可见 |

**场景**：消息传递、**互斥锁 / 自旋锁**（先写数据，再 Release 标志；读标志用 Acquire，再读数据）。

→ 代码：[2.1-atomic-load-store-demo.rs](../Chapter-02-Atomics/2.1-atomic-load-store/2.1-atomic-load-store-demo.rs) · 第 4 章：[4.1-minimal-implementation-demo.rs](../Chapter-04-Spin-Locks/4.1-minimal-implementation/4.1-minimal-implementation-demo.rs)

---

## ④ `Ordering::AcqRel`（获取并释放）

| 项 | 内容 |
|----|------|
| **用于** | **RMW**（`fetch_add`、`compare_exchange`、`swap` 等） |
| **语义** | 读侧 **Acquire** + 写侧 **Release** 合一 |
| **场景** | 单次原子操作既要「看见之前发布」又要「向后续发布」 |

---

## ⑤ `Ordering::SeqCst`（顺序一致）

| 项 | 内容 |
|----|------|
| **保证** | 含 Acquire/Release 约束 + 所有 **SeqCst** 操作共有一条 **全局严格总顺序** |
| **效果** | 所有线程对 SeqCst 操作看到**同一条时间线** |
| **场景** | **极少** — 如书中「双旗帜」：需根据**两个不同原子**写入的**全局先后**做决策 |
| **审查** | 代码里大量 SeqCst 常是**警告信号**（未分析清需求或偷懒） |

---

## 对照表（必背）

| Ordering | 跨线程 HB | 重排限制（口语） | 典型场景 | 性能（相对） |
|----------|-----------|------------------|----------|--------------|
| **Relaxed** | ❌ 无 | 最弱；只保单原子总序 | 独立计数、进度、Stop Flag（不同步别内存） | 最省 |
| **Release** | ✅ 与配对 Acquire | 之前写不能排到 store 后 | 发布数据后写标志、**解锁** | 中等 |
| **Acquire** | ✅ 读到 Release 后 | 之后读不能排到 load 前 | 读标志后读数据、**加锁** | 中等 |
| **AcqRel** | ✅ RMW 双向 | 读 Acquire + 写 Release | `fetch_*` / CAS / `swap` 当同步点 | 中等 |
| **SeqCst** | ✅ + 全局 SeqCst 序 | 最强；所有 SeqCst 共一条时间线 | 多原子全局先后决策 | 最重（ARM 上尤甚） |

### 适用场景速查

| 你的需求 | 选什么 |
|----------|--------|
| 只改一个原子计数，不同步其它变量 | **Relaxed** |
| 原子是「数据已就绪」信使 | **Release**（写）+ **Acquire**（读） |
| 自旋锁 / Mutex 语义 | lock：**Acquire**（或 AcqRel 的 swap）；unlock：**Release** |
| RMW 同时发布又订阅 | **AcqRel** |
| 必须比较两个原子在**全局**的先后 | 才考虑 **SeqCst** |

---

## 选型口诀（弱 → 强）

```text
  信使原子同步普通内存？ → 禁止 Relaxed，用 Release/Acquire（或 AcqRel 的 RMW）
  仅单变量统计？           → Relaxed
  多原子全局时间线？       → 才考虑 SeqCst
```
