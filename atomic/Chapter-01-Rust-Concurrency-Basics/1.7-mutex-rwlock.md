## 1.7 Locking: Mutexes and RwLocks（互斥锁与读写锁）

> 书 §1.7 · 承接 [1.5 内部可变性](./1.5-interior-mutability.md)、[1.6 Sync](./1.6-send-sync.md) · 全书深度：[互斥锁与锁体系-贯通笔记.md](../互斥锁与锁体系-贯通笔记.md)、[RwLock与读写锁体系-贯通笔记.md](../RwLock与读写锁体系-贯通笔记.md)

## 一、为什么需要 Mutex

[1.4](./1.4-borrowing-data-races.md)：**共享读 OR 独占写**。多线程要**改**同一份 `T`，不能同时拿多个 `&mut` → 用 **`Mutex<T>`**（互斥锁）把「排他访问」放到**运行时**，冲突时**阻塞**而不是 panic。

与 C++「锁与数据分离」不同：Rust **`Mutex<T>` 包裹数据**，类型系统保证**不加锁拿不到 `&mut T`**。

---

## 二、`Mutex<T>` 基本用法

**一句话**：`lock()` 阻塞直到拿到锁 → 返回 **`MutexGuard<T>`** → 通过 **`DerefMut`** 当 `&mut T` 用 → **Drop 时自动解锁**（RAII）。

```rust
use std::sync::Mutex;

let m = Mutex::new(5);
{
    let mut guard = m.lock().unwrap();
    *guard += 10;
} // guard drop → 解锁
println!("{}", m.lock().unwrap());
```

仓库对应：[1.7-mutex-rwlock-mutex-demo.rs](./1.7-mutex-rwlock/1.7-mutex-rwlock-mutex-demo.rs) — `demo_mutex_guard`

### 多线程累加模板

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let n = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..10 {
    let n = Arc::clone(&n);
    handles.push(thread::spawn(move || {
        for _ in 0..100 {
            *n.lock().unwrap() += 1;
        }
    }));
}
for h in handles {
    h.join().unwrap();
}
assert_eq!(*n.lock().unwrap(), 1000);
```

仓库对应：`demo_multithread_increment`

## MutexGuard\<T\> 精读

### 1. 是什么

- **`lock()`** → `Result<MutexGuard<T>, PoisonError>`
- **`MutexGuard`**：持锁标记 + 智能指针语义；**不能**安全地越过线程边界发送（guard 非 `Send` 的设计避免锁状态错乱）。

### 2. RAII 与作用域

```rust
let mutex = Mutex::new(0);
{
    let mut g = mutex.lock().unwrap();
    *g += 10;
} // 此处锁已释放
let g2 = mutex.lock().unwrap(); // 可再次获取
```

仓库对应：[1.7-mutex-rwlock-guard-lifetime-demo.rs](./1.7-mutex-rwlock/1.7-mutex-rwlock-guard-lifetime-demo.rs) — `demo_guard_lifetime`

### 3. 锁作用域陷阱（高频）

```rust
// ❌ guard 活整个 if 块，锁占用过久
if let Some(item) = list.lock().unwrap().pop() {
    slow_work(item); // 仍持锁！
}

// ✅ 先 pop，再处理
let item = {
    let mut guard = list.lock().unwrap();
    guard.pop()
};
if let Some(item) = item {
    slow_work(item);
}
```

`if let`、`match`、`while let` 里直接 `lock()` 都会让 **guard 绑定到整个分支块**。

仓库对应：`demo_guard_lifetime_mistake`、`demo_guard_lifetime_correct`

### 4. 锁内不要 `sleep`

持锁期间 `thread::sleep` 会阻塞其他线程拿锁 → 并行变串行。应**尽快 drop guard** 再做耗时 I/O。

## 三、锁中毒（Lock Poisoning）

持锁线程 **panic** 时，Rust 将 `Mutex` 标记为 **poisoned（中毒）**：防止其他线程在数据可能不一致时继续用。

```rust
let m = Mutex::new(0);
// 若某线程 lock 后 panic，后续 lock() 得 Err(PoisonError)
match m.lock() {
    Ok(guard) => { /* 正常 */ }
    Err(poison) => {
        // poison.into_inner() 仍可强行取 guard（接受风险）
    }
}
```

日常 `.unwrap()` = 「接受中毒、继续用内部 guard」。生产环境可记录日志或重建状态。

仓库对应：`demo_lock_poisoning`

## 四、`RwLock<T>` 概要

**多读 OR 一写**：

| Guard | 含义 |
|-------|------|
| **`ReadGuard`** | 多个线程可同时读 |
| **`WriteGuard`** | 独占写；与任何读/写互斥 |

适用**读多写少**；注意 **写者饥饿（Writer Starvation）**：读者持续占锁时写者可能长期等待。

全书状态机、写优先策略见 [RwLock与读写锁体系-贯通笔记.md](../RwLock与读写锁体系-贯通笔记.md)。

```rust
use std::sync::RwLock;

let lock = RwLock::new(5);
{
    let r1 = lock.read().unwrap();
    let r2 = lock.read().unwrap();
    println!("{} {}", *r1, *r2);
}
{
    let mut w = lock.write().unwrap();
    *w += 1;
}
```

## 五、对照：`Mutex` vs `RwLock` vs `RefCell`

| | **`RefCell`** | **`Mutex`** | **`RwLock`** |
|---|---------------|-------------|--------------|
| 线程 | 单线程 | 多线程 | 多线程 |
| 冲突 | panic | 阻塞 | 阻塞 |
| 并发读 | 多个 `borrow` | ❌ 互斥 | ✅ 多个 `read` |
| 典型组合 | `Rc<RefCell<T>>` | `Arc<Mutex<T>>` | `Arc<RwLock<T>>` |

## 六、其他 API（了解）

| API | 作用 |
|-----|------|
| **`into_inner()`** | 消耗 `Mutex`，取出内部 `T`（需已解锁） |
| **`get_mut(&mut self)`** | 独占可变引用时无需加锁直接改 |

## 七、新手易错

1. **`if let` 里 `lock()`** → guard 生命周期过长（见上）。
2. **死锁**：线程 A 持锁 1 等 2，B 持 2 等 1 → 固定加锁顺序。
3. **忘记 `Arc`**：多线程共享同一把 `Mutex` 须 `Arc<Mutex<T>>`。
4. **读多写少仍用 `Mutex`**：可评估 `RwLock`；但 `RwLock` 也有写者饥饿。
