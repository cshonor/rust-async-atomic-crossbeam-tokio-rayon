## 1.3 Shared Ownership（共享所有权与引用计数）

> 书 §1.3 · 承接 [1.1 spawn / `'static`](./1.1-threads-in-rust.md)、[1.2 scope](./1.2-scoped-threads.md) · 可变共享见 [1.5 内部可变性](./1.5-interior-mutability.md)、[1.7 Mutex](./1.7-mutex-rwlock.md)

---

## 一、为什么需要共享所有权

`thread::spawn` 要求 **`'static`**：子线程可能比创建它的栈帧活得更久，因此**不能借用**局部变量。常见出路：

| 场景 | 做法 |
|------|------|
| 子线程一定在函数返回前结束 | [1.2 `thread::scope`](./1.2-scoped-threads.md) 借用局部变量 |
| 多个子线程寿命都不确定，要**同读**一份数据 | **`Arc`**（或 `'static` / leak） |
| 单线程内多处共享 | **`Rc`** |

**核心问题**：数据要活得和**最长寿程**一样久；`Rc`/`Arc` 用**引用计数**让堆上数据在所有 `clone` 出的句柄都 drop 后才释放。

---

## 二、四种让数据「活得够久」的方式

| 方式 | 说明 | 注意 |
|------|------|------|
| **`static`** | 全程序生命周期，编译期分配或链接 | 任何线程可借 `'static` 引用 |
| **`Box::leak`** | 主动放弃所有权，得 **`&'static T`** | 实质**内存泄漏**；频繁调用会耗尽内存 |
| **`Rc` / `Arc`** | 堆上数据 + 引用计数；计数为 0 释放 | **`Rc` 非线程安全**；跨线程必须用 **`Arc`** |
| **克隆 + 变量遮蔽** | `let a = a.clone();` 再 `move \|…` | 避免 `a1,a2,a3…` 重命名地狱 |

---

## 三、`Rc<T>` 与 `Arc<T>` 精读

**一句话**：`Rc::new(x)` / `Arc::new(x)` 在堆上创建 `x`，栈上只留**智能指针**；`clone()` **只增计数、不复制堆数据**。

```rust
use std::rc::Rc;

let rc1 = Rc::new(42);
let rc2 = Rc::clone(&rc1); // 计数 2，仍指向同一块堆内存
println!("{} {}", rc1, rc2);
```

### 1. 共同点：默认只能共享读

`Rc<T>` / `Arc<T>` 提供的是 **`&T` 级别的共享**，**不能直接 `*rc = …` 修改**。要改内部数据 → 配合 `RefCell` / `Mutex`（见 [1.5](./1.5-interior-mutability.md)、[1.7](./1.7-mutex-rwlock.md)）。

### 2. 关键区别

| | **`Rc<T>`** | **`Arc<T>`** |
|---|-------------|--------------|
| 模块 | `std::rc` | `std::sync` |
| 计数更新 | 普通整数加减 | **原子**操作 |
| 跨线程 | ❌ 不能 `Send` | ✅ 可 `spawn` + `clone` 分发 |
| 性能 | 略快（无原子开销） | 略慢 |
| 典型组合 | `Rc<RefCell<T>>` | `Arc<Mutex<T>>`、`Arc<RwLock<T>>` |

```rust
use std::sync::Arc;
use std::thread;

let arc = Arc::new(100);
let a = Arc::clone(&arc);
let h = thread::spawn(move || println!("{a}"));
h.join().unwrap();
println!("主线程仍可读: {arc}");
```

仓库对应：[1.3-shared-ownership-arc-demo.rs](./1.3-shared-ownership/1.3-shared-ownership-arc-demo.rs)

### 3. 易错：`Rc` 进子线程

```rust
// let rc = Rc::new(42);
// thread::spawn(move || { println!("{rc}"); }); // 编译错误：Rc 非 Send
```

## 四、`static` 与 `Box::leak`

### 1. `static`

编译期或链接期存在的全局数据，类型天然带 **`'static`** 生命周期：

```rust
static GREETING: &str = "Greetings from a 'static string!";

thread::spawn(|| println!("{GREETING}")).join().unwrap();
```

仓库对应：[1.3-shared-ownership-static-demo.rs](./1.3-shared-ownership/1.3-shared-ownership-static-demo.rs)

### 2. `Box::leak`

把堆数据**永久泄漏**成 `'static` 引用，适合「进程级只泄漏一次」的场景：

```rust
let leaked: &'static str = {
    let s = String::from("Hello from a leaked Box!");
    Box::leak(s.into_boxed_str())
};

thread::spawn(move || println!("{leaked}")).join().unwrap();
```

仓库对应：[1.3-shared-ownership-box-leak-demo.rs](./1.3-shared-ownership/1.3-shared-ownership-box-leak-demo.rs)

> **选型**：优先 `Arc`；`leak` 是刻意放弃回收；`static` 适合真正全局常量。

---

## 五、克隆 + 变量遮蔽（多线程分发 Arc）

多个 `spawn` 都要 `move` 同一份 `Arc`，若每次 `let a1 = a.clone()` 会很快变成命名地狱。**变量遮蔽**写法：

```rust
use std::sync::Arc;
use std::thread;

let a = Arc::new(vec![1, 2, 3]);
let mut handles = vec![];

for _ in 0..3 {
    let a = Arc::clone(&a); // 遮蔽外层 a，闭包里 move 的是 clone
    handles.push(thread::spawn(move || {
        println!("{:?}", a);
    }));
}

for h in handles {
    h.join().unwrap();
}
// 外层 a 仍可用
```

**要点**：`Arc::clone` 只增引用计数，**不复制 `Vec` 本体**；每个线程 `move` 走的是栈上的 `Arc` 句柄。

---

## 六、对照：scope vs Arc vs `'static`

| | **`thread::scope`** | **`Arc<T>`** | **`'static` / leak** |
|---|---------------------|--------------|----------------------|
| 数据位置 | 常在栈上 | 堆 + 计数 | 全局或泄漏堆 |
| 线程寿命 | 限于 scope | 任意 | 任意 |
| 可变共享 | 须额外同步类型 | 须 `Mutex` 等 | 须 `Mutex` 或原子 |
| 典型用途 | 短生命周期并行 | 长期多线程只读/加锁写 | 全局配置、一次性泄漏 |

---

## 七、新手易错

1. **以为 `Arc::clone` 复制了数据**：只复制指针并 `+1` 计数。
2. **用 `Rc` 做跨线程共享**：编译期会拦；换 `Arc`。
3. **只有 `Arc` 就能改数据**：不行，默认只读；改要用 `Arc<Mutex<T>>`。
4. **滥用 `Box::leak`**：泄漏不可回收，测试/临时方案可以，生产要谨慎。
