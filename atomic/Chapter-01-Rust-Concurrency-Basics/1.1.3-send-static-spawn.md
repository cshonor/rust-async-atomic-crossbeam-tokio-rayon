## 1.1.3 spawn 的 `Send + 'static` 约束

> 书 §1.1（续）· [1.1.1 spawn/join](./1.1.1-spawn-join-basics.md) · [1.1.2 JoinHandle](./1.1.2-join-handle.md) · 绕过 `'static`：[1.2 scope](./1.2-scoped-threads.md) · [1.3 Arc](./1.3-shared-ownership.md) · [1.6 Send/Sync](./1.6-send-sync.md)

**结论**：**`F: 'static` 不是编译器乱加的，是 `std::thread::spawn` 函数签名写死的**——线程可能比创建它的函数活得更久，必须杜绝悬垂引用。高频路径常用 **`thread::scope`** 等有界生命周期写法绕过（见 [§七](#七绕过-static借局部变量--threadscope)、[§八](#八hft-语境与学习顺序)）。

---

## 一、`spawn` 完整签名（逐条拆解）

> 是 **`spawn`**（创建线程），不是 swap（交换）。

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T,  // 约束 1：闭包特征 + 返回 T
    F: Send,            // 约束 2：闭包可跨线程发送
    F: 'static,         // 约束 3：闭包捕获物须「活得够久」
    T: Send + 'static,  // 约束 4：返回值可跨线程传回
```

（标准库把 1–3 合并写成 `F: FnOnce() -> T + Send + 'static`。）

| # | 约束 | 对象 | 干什么 |
|---|------|------|--------|
| **1** | `F: FnOnce() -> T` | 闭包 | 无参、**只执行一次**的线程入口；`T` = 闭包返回值 → `JoinHandle<T>` 里的 `T`（见 [1.1.2](./1.1.2-join-handle.md)） |
| **2** | `F: Send` | 闭包 | 闭包**整体所有权**可安全 **move 到子线程**；`Rc`、裸指针等 **非 Send** → 编译拒绝 |
| **3** | `F: 'static` | 闭包 | 捕获的数据**不能是短生命周期借用**；子线程可能比创建者栈帧活得更久 |
| **4** | `T: Send + 'static` | 返回值 | `join` 把 **`T` move 回**等待线程；`JoinHandle` 可存到函数外 → **`T` 也不能带悬垂引用** |

### 约束 1：`FnOnce() -> T`

线程入口**只跑一遍**，故是 **`FnOnce`**，不是 `Fn` / `FnMut`（语义见 [1.1.4](./1.1.4-closure-traits-fnonce.md)）。

### 约束 2：`F: Send`

`spawn` 在**当前线程**构造闭包，再 **move 给新 OS 线程**执行 → 闭包及其捕获物必须 **`Send`**。

### 约束 3：`F: 'static` — **来自 `spawn` 签名，为防悬垂引用**

#### `'static` 从哪来？

`std::thread::spawn` 大致长这样（简化）：

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T + Send + 'static,  // 👈 这里写死了 F: 'static
    T: Send + 'static,
{
    // ...
}
```

只要你调用 `thread::spawn(move || { ... })`，闭包类型 **`F`** 就必须满足 **`FnOnce` + `Send` + `'static`**。**约束 3 是 spawn API 自带的，不是凭空来的。**

#### 为什么 spawn 要 `F: 'static`？

主线程可能先跑完、栈被销毁，**子线程还在跑**。若闭包捕获 **`&'a x`**（`x` 在栈上），就是**悬垂引用（野指针）**。

典型错误（编译不通过）：

```rust
use std::thread;

fn main() {
    let local = String::from("hello"); // 栈上，生命周期到 main 结束
    let r = &local;                    // &'a，'a = main 的生命周期

    thread::spawn(move || {
        println!("{r}"); // ❌ 闭包里有 &'a，不是 'static
    });
}
```

| 问题 | 说明 |
|------|------|
| `local` 销毁 | 主线程 / 创建者栈帧结束时，`local` 被 drop |
| `r` 变悬垂 | 子线程若仍在跑，`r` 指向已释放内存 |
| Rust 对策 | **禁止**把含非 `'static` 引用的闭包传给 `spawn` |

**`'static` 在此的实用含义**：闭包**不能借**「可能比线程活得短」的数据；只能 **move 所有权**（owned 随闭包进子线程）或使用 **`'static` / 全局** 数据。

> `T: 'static` 同理：类型**不包含任何非 `'static` 的引用**，可以安全地一直存到程序结束（或等价地：经 `join` / `JoinHandle` 传回时不带悬垂借）。

### 约束 4：`T: Send + 'static`

- **`Send`**：`T` 要能经 `join` **跨线程**传回；
- **`'static`**：`JoinHandle<T>` 可以留存任意久，`T` 不能内含短期借用。

### 反例 + `move` 修复

```rust
let x = 10;
// 报错：F 不满足 'static——闭包借用栈上 x
let h = thread::spawn(|| dbg!(x));

// 修复：move 把 x 所有权移入闭包（owned 数据随闭包进子线程，不再依赖外层栈）
let h = thread::spawn(move || dbg!(x));
```

### 为什么 F 和 T 都要 `'static`？（双重 static）

| 对象 | 原因 |
|------|------|
| **`F`** | 闭包逻辑要在子线程里跑，线程寿命 **不受**创建者栈帧限制 |
| **`T`** | 返回值经 `JoinHandle` 保存，可能在 **join 之前**被带到函数外；不能带「比 handle 活得短」的引用 |

## 二、为什么必须 `Send`？

**`Send`**：类型可以**安全地把所有权从一个线程转移到另一个线程**。

`spawn` 时发生的事：

1. 在**当前线程**构造闭包 `F`；
2. `spawn` 把闭包 **move 到新 OS 线程**执行；
3. 子线程结束后，`join` 把 **`T` move 回**等待线程。

若闭包内含 **`Rc<T>`** 等非 `Send` 类型，跨线程 move 会破坏 `Rc` 不变量（非原子计数）→ **数据竞争 / 双重释放**。编译器用 **`F: Send`** 禁止。

**一句话**：**`Send` 保证闭包能安全「搬家」到新线程**。

---

## 三、为什么必须 `'static`？

**`'static` 不是一种「数据类型」**，而是**生命周期标注**：在此表示「捕获的数据须在整个程序运行期都有效」（或等价地：**不能是依赖当前栈帧的短期借用**）。

**`F: 'static` 的本质规则**：子线程**生命周期不受任何代码块限制**——主线程可以先结束、销毁栈上变量，子线程还能继续跑。若闭包捕获 **`&'a T`** 且 `'a` 只覆盖当前函数栈 → 悬垂引用。

Rust 的两种合法方案：

| 方案 | 做法 | 说明 |
|------|------|------|
| **1. move 所有权** | `spawn(move \|\| …)` | 闭包**拥有** `String` / `i32` 等 owned 数据，**不再借用**外层栈；满足 `Send + 'static` |
| **2. 真·`'static` 数据** | `&'static str`、全局 `static` | 数据本身就在整个程序期有效 |

风险模型：

- 子线程可能 **detach**（drop `JoinHandle` 未 join）或比创建者**活得更久**；
- 若闭包里有 **`&'a 局部变量`**，创建者栈帧销毁后 → **悬垂引用**。

编译器无法证明线程何时结束，故对 **`thread::spawn` 保守要求 `'static`**。

**一句话**：**`thread::spawn` — 线程可能活过当前栈 → 强制 `'static`，通常用 `move` 拿所有权；借局部栈 → [1.2.4 `'scope` 深拆](./1.2.4-scoped-join-handle.md#static-vs-scope生命周期深拆)。**

> 精确说法：`move` 转移 **owned** 的 `String` 等即可，**不必**字面量写 `&'static`；关键是闭包捕获的类型满足 **`Send + 'static`**。

```rust
let num = 10;
// 报错：闭包借用 &num，生命周期只有 'a（当前栈），不是 'static
// let h = thread::spawn(|| println!("{num}"));

let h = thread::spawn(move || println!("{num}")); // num 所有权进闭包
```

## 四、常见错误：借用局部变量

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    // 错误：闭包捕获 &s，生命周期不是 'static
    let h = thread::spawn(|| {
        println!("{s}");
    });

    h.join().unwrap();
}
```

典型报错：`error[E0597]: 's' does not live long enough` — 闭包需要 **`'static`**，不能借有限生命周期的 `s`。

仓库对照：[move-closure-demo.rs](./1.1-threads-in-rust/1.1-threads-in-rust-move-closure-demo.rs)（正确写法）

## 五、正确写法：`move` 转移所有权

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    let h = thread::spawn(move || {
        println!("{s}"); // 闭包拥有 s
    });

    h.join().unwrap();
}
```

| 要点 | 说明 |
|------|------|
| **`move`** | 强制闭包**取得**捕获变量的所有权，不再借用 |
| **为何满足约束** | owned 的 `String` 随闭包进子线程，**不依赖**外层栈帧 |

## 六、多线程共享：只读 `Arc`

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let s = Arc::new(String::from("hello"));
    let mut handles = vec![];

    for _ in 0..2 {
        let s = Arc::clone(&s); // 只增引用计数
        handles.push(thread::spawn(move || {
            println!("{s}");
        }));
    }
    for h in handles {
        h.join().unwrap();
    }
}
```

- **`Arc<T>`**：`T: Send + Sync` 时 **`Arc` 可 Send**，多线程共享**只读**；
- 可变共享 → **`Arc<Mutex<T>>`**（[1.7](./1.7-mutex-rwlock.md)）。

## 七、绕过 `'static`：借局部变量 → `thread::scope`

若必须**借用**栈上数据、且线程**一定在函数返回前结束**，用 **`thread::scope`**（`F: 'scope`，不要 `'static`）：

```rust
let local = String::from("hello"); // 栈上，须在 scope 外定义才能被 s.spawn 借用
thread::scope(|s| {
    s.spawn(|| println!("{local}")).join().unwrap(); // ✅ 借 local
});
```

> **注意**：`local` 若定义在 **`scope` 闭包内部**，`s.spawn` 仍常须 **`move`**（与 [1.2 demo](./1.2-scoped-threads/1.2-scoped-threads-demo.rs) 一致）；对比重点是 **scope 外栈变量可借、`spawn` 不行**。

| | `thread::spawn` | `thread::scope` + `s.spawn` |
|--|-----------------|----------------------------|
| 闭包约束 | **`F: 'static`** | **`F: 'scope`** |
| 借栈上局部 | ❌ | ✅（scope 结束前线程必结束） |
| 典型用途 | Detached 工作线程、线程池任务 | 函数内有界并行、可预测 join |

**最小可运行对比** → [1.1-threads-in-rust-static-vs-scope-demo.rs](./1.1-threads-in-rust/1.1-threads-in-rust-static-vs-scope-demo.rs)（`move` 版 spawn + 借用版 scope；文件内注释含「编译报错版」）。

详见 [1.2 Scoped Threads](./1.2-scoped-threads.md)、[1.2.4 `'static` vs `'scope` 深拆](./1.2.4-scoped-join-handle.md#static-vs-scope生命周期深拆)。

## 八、HFT 语境与学习顺序

**结论**：**`spawn` + `'static` 是基础多线程模型，HFT 里会用到，但不是核心瓶颈**；HFT 更怕的是**锁、系统调用、分配、缓存失效**，而不是 `'static` 标注本身。

### HFT 里对应的场景

| 场景 | 常见写法 | 与 `'static` 的关系 |
|------|----------|---------------------|
| **线程池 / 控盘 / 监控** | `spawn` 或线程池，任务闭包 **`'static`** | 数据 **`move`** 进闭包，或 **`Arc`** 共享；延迟要求相对宽松 |
| **订单 / 行情关键路径** | 少用裸 `spawn`；多用 **`thread::scope`**、线程局部 + 无锁队列 + 轮询 | 要**有界生命周期、可控 join**；`'static` 不是问题，**线程创建与管理**才引入不可控延迟 |

### 建议学习顺序（面向系统 / HFT 方向）

1. **`std::sync`**（锁）、**`Arc`**、**`Mutex`**、**`Condvar`**、**`thread::scope`** → 共享状态、线程协作、安全访问  
2. **`tokio` / async**、**TCP/UDP** → 行情、订单、数据链路  
3. **过程宏** → 放最后；核心路径几乎不用，多用于序列化、配置、代码生成等辅助

**一句话**：**`F: 'static` 来自 `spawn` 签名，防子线程拿着栈引用乱跑**；HFT 高频路径优先 **scope / 无锁结构** 等更轻量、生命周期可控的写法。

## 九、场景对照表（错误 / 正确 / 原因）

| 场景 | ❌ 常见错误 | ✅ 正确写法 | 原因 |
|------|------------|------------|------|
| 局部 `String` 进子线程 | `spawn(\|\| println!("{s}"))` 无 move | `spawn(move \|\| …)` | 不能捕获 `&s`；须 **owned + Send** |
| 多个线程读同一份数据 | `Rc::clone` + `spawn` | **`Arc::clone` + `move`** | **`Rc` 非 Send** |
| 多个线程改同一份数据 | 多个 `move` 抢同一 `String` | **`Arc<Mutex<T>>`** | 要 **Sync + 互斥** |
| 短生命周期借用 | `spawn(\|\| use &local)` | **`thread::scope`** | `'static` 不允许借栈 |
| 全局配置 | — | **`static` / `LazyLock`** | 天然 `'static` |
| 子线程必在 fn 内结束 | 手动 join 列表 | **`thread::scope`** | 自动 join + 允许借用 |
| 返回值回主线程 | 返回 `&local` | 返回 **owned `T`** 且 **`T: Send`** | `join` 也要 **`T: Send`** |

---

## 十、背诵版

1. **`spawn`**（不是 swap）；签名 **`F: FnOnce() -> T + Send + 'static`**，**`T: Send + 'static`** — **`'static` 是签名写死的**，防悬垂引用。  
2. **`Send`**：闭包与返回值能**安全跨线程 move**。  
3. **`'static`**：**F 与 T 都要**——不捕获短借用；局部 owned 用 **`move`**；借栈 → **`thread::scope`**（[§七](#七绕过-static借局部变量--threadscope)）。  
4. **共享**：只读 **`Arc`**；可写 **`Arc<Mutex<T>>`**；HFT 关键路径优先 **scope / 无锁**（[§八](#八hft-语境与学习顺序)）。
