## 1.1.3 spawn 的 `Send + 'static` 约束

## 一、`spawn` 完整签名（逐条拆解）

> 是 **`spawn`**（创建线程），不是 swap（交换）。

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T,  // 约束 1：闭包特征 + 返回 T
    F: Send,            // 约束 2：闭包可跨线程发送
    F: 'static,         // 约束 3：闭包捕获物须「活得够久」
    T: Send + 'static,  // 约束 4：返回值可跨线程传回
```

（标准库把 1–3 合并写成 `F: FnOnce() -> T + Send + 'static`。）

| # | 约束 | 对象 | 干什么 |
|---|------|------|--------|
| **1** | `F: FnOnce() -> T` | 闭包 | 无参、**只执行一次**的线程入口；`T` = 闭包返回值 → `JoinHandle<T>` 里的 `T`（见 [1.1.2](./1.1.2-join-handle.md)） |
| **2** | `F: Send` | 闭包 | 闭包**整体所有权**可安全 **move 到子线程**；`Rc`、裸指针等 **非 Send** → 编译拒绝 |
| **3** | `F: 'static` | 闭包 | 捕获的数据**不能是短生命周期借用**；子线程可能比创建者栈帧活得更久 |
| **4** | `T: Send + 'static` | 返回值 | `join` 把 **`T` move 回**等待线程；`JoinHandle` 可存到函数外 → **`T` 也不能带悬垂引用** |

### 约束 1：`FnOnce() -> T`

线程入口**只跑一遍**，故是 **`FnOnce`**，不是 `Fn` / `FnMut`（语义见 [1.1.4](./1.1.4-closure-traits-fnonce.md)）。

### 约束 2：`F: Send`

`spawn` 在**当前线程**构造闭包，再 **move 给新 OS 线程**执行 → 闭包及其捕获物必须 **`Send`**。

### 约束 3：`F: 'static`（`'static` 从哪来）

主线程可能先跑完、栈被销毁，子线程还在跑。若闭包捕获 **`&'a x`**（`x` 在栈上），就是悬垂引用。

**`'static` 在此的实用含义**：闭包**不能借**「可能比线程活得短」的局部变量；只能 **move 所有权**（owned 数据随闭包进子线程）或使用 `'static` 数据。

### 约束 4：`T: Send + 'static`

- **`Send`**：`T` 要能经 `join` **跨线程**传回；
- **`'static`**：`JoinHandle<T>` 可以留存任意久，`T` 不能内含短期借用。

### 反例 + `move` 修复

```rust
let x = 10;
// 报错：F 不满足 'static——闭包借用栈上 x
let h = thread::spawn(|| dbg!(x));

// 修复：move 把 x 所有权移入闭包（owned i32 不依赖外层栈）
let h = thread::spawn(move || dbg!(x));
```

### 为什么 F 和 T 都要 `'static`？（双重 static）

| 对象 | 原因 |
|------|------|
| **`F`** | 闭包逻辑要在子线程里跑，线程寿命 **不受**创建者栈帧限制 |
| **`T`** | 返回值经 `JoinHandle` 保存，可能在 **join 之前**被带到函数外；不能带「比 handle 活得短」的引用 |

## 二、为什么必须 `Send`？

**`Send`**：类型可以**安全地把所有权从一个线程转移到另一个线程**。

`spawn` 时发生的事：

1. 在**当前线程**构造闭包 `F`；
2. `spawn` 把闭包 **move 到新 OS 线程**执行；
3. 子线程结束后，`join` 把 **`T` move 回**等待线程。

若闭包内含 **`Rc<T>`** 等非 `Send` 类型，跨线程 move 会破坏 `Rc` 不变量（非原子计数）→ **数据竞争 / 双重释放**。编译器用 **`F: Send`** 禁止。

**一句话**：**`Send` 保证闭包能安全「搬家」到新线程**。

---

## 三、为什么必须 `'static`？

**`'static`**（在此处的实用含义）：闭包**不能捕获**「可能比线程活得短」的**借用**（如 `&'a T` 且 `'a` 不是 `'static`）。

风险模型：

- 子线程可能 **detach**（drop `JoinHandle` 未 join）或比创建者**活得更久**；
- 若闭包里有 **`&'a 局部变量`**，创建者栈帧销毁后 → **悬垂引用**。

编译器无法证明线程何时结束，故保守要求：**只用 `'static` 数据，或把所有权 move 进闭包**（owned 数据随线程一起活）。

**一句话**：**`'static` 防止线程还在跑时，被引用的数据先被销毁**。

> 精确说法：捕获的类型须满足 **`Send + 'static`**；`move ||` 转移 **owned** 的 `String` 等即可，不必字面量 `'static` 生命周期。

## 四、常见错误：借用局部变量

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    // 错误：闭包捕获 &s，生命周期不是 'static
    let h = thread::spawn(|| {
        println!("{s}");
    });

    h.join().unwrap();
}
```

典型报错：`error[E0597]: 's' does not live long enough` — 闭包需要 **`'static`**，不能借有限生命周期的 `s`。

仓库对照：[move-closure-demo.rs](./1.1-threads-in-rust/1.1-threads-in-rust-move-closure-demo.rs)（正确写法）

## 五、正确写法：`move` 转移所有权

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    let h = thread::spawn(move || {
        println!("{s}"); // 闭包拥有 s
    });

    h.join().unwrap();
}
```

| 要点 | 说明 |
|------|------|
| **`move`** | 强制闭包**取得**捕获变量的所有权，不再借用 |
| **为何满足约束** | owned 的 `String` 随闭包进子线程，**不依赖**外层栈帧 |

## 六、多线程共享：只读 `Arc`

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let s = Arc::new(String::from("hello"));
    let mut handles = vec![];

    for _ in 0..2 {
        let s = Arc::clone(&s); // 只增引用计数
        handles.push(thread::spawn(move || {
            println!("{s}");
        }));
    }
    for h in handles {
        h.join().unwrap();
    }
}
```

- **`Arc<T>`**：`T: Send + Sync` 时 **`Arc` 可 Send**，多线程共享**只读**；
- 可变共享 → **`Arc<Mutex<T>>`**（[1.7](./1.7-mutex-rwlock.md)）。

## 七、绕过 `'static`：借局部变量 → `thread::scope`

若必须**借用**栈上数据、且线程**一定在函数返回前结束**：

```rust
thread::scope(|s| {
    let local = vec![1, 2, 3];
    s.spawn(|| println!("{:?}", local)); // 借 local，不必 move 整份 Vec
});
```

见 [1.2 Scoped Threads](./1.2-scoped-threads.md)。

## 八、场景对照表（错误 / 正确 / 原因）

| 场景 | ❌ 常见错误 | ✅ 正确写法 | 原因 |
|------|------------|------------|------|
| 局部 `String` 进子线程 | `spawn(\|\| println!("{s}"))` 无 move | `spawn(move \|\| …)` | 不能捕获 `&s`；须 **owned + Send** |
| 多个线程读同一份数据 | `Rc::clone` + `spawn` | **`Arc::clone` + `move`** | **`Rc` 非 Send** |
| 多个线程改同一份数据 | 多个 `move` 抢同一 `String` | **`Arc<Mutex<T>>`** | 要 **Sync + 互斥** |
| 短生命周期借用 | `spawn(\|\| use &local)` | **`thread::scope`** | `'static` 不允许借栈 |
| 全局配置 | — | **`static` / `LazyLock`** | 天然 `'static` |
| 子线程必在 fn 内结束 | 手动 join 列表 | **`thread::scope`** | 自动 join + 允许借用 |
| 返回值回主线程 | 返回 `&local` | 返回 **owned `T`** 且 **`T: Send`** | `join` 也要 **`T: Send`** |

---

## 九、背诵版

1. **`spawn`**（不是 swap）；签名 **`F: FnOnce() -> T + Send + 'static`**，**`T: Send + 'static`**。  
2. **`Send`**：闭包与返回值能**安全跨线程 move**（两个 spawn 都要 **`F: Send`**）。  
3. **`'static`**：**F 与 T 都要**——不捕获短借用；局部 owned 用 **`move`**。  
4. **共享**：只读 **`Arc`**；可写 **`Arc<Mutex<T>>`**；只借局部 → **`s.spawn`**（[1.2 §约束对照](./1.2-scoped-threads.md#两段-spawn-泛型约束对照)）。
