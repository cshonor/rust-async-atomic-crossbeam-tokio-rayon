## 6. 本章核心术语

| 术语 | 含义 |
|------|------|
| **Shared / Exclusive Reference** | `&T` / `&mut T` 的准确叫法 |
| **Data Race** | 并发读写同内存 → UB |
| **Interior Mutability** | 通过 `&T` 改内部数据 |
| **Send / Sync** | 跨线程移所有权 / 跨线程共享引用 |
| **Lock Poisoning** | 持锁 panic 后锁状态保护 |
| **Spurious Wake-up** | park / condvar 无明确信号也可能醒 → **必须 `loop` 查条件** |
| **Leakpocalypse** | 依赖 Drop 的 scoped 线程 API 因 leak 而 Unsound |
| **Writer Starvation** | `RwLock` 读者不断占锁，写者永远拿不到 |

## 8. 新手必备认知与易错点

### 必备认知

1. **不要靠「一定会 Drop」设计安全**：循环引用、`mem::forget` 等可不调用 Drop → 早期 `thread::scoped` 类 API 不安全（**Leakpocalypse**）。  
2. **先解决所有权与生命周期**：报错时想 **`scope`** 还是 **`Arc`**。  
3. **`Mutex` 保护的是数据**：要改必先拿锁；类型系统禁止「裸引用绕过锁」。

### 高频易错点

| # | 坑 | 正确做法 |
|---|-----|----------|
| 1 | **锁持有过久** | `MutexGuard` 绑作用域；I/O / `sleep` 前用 `{}` 或 `drop(guard)` |
| 2 | **`if let` 延长锁** | `if let Some(x) = list.lock().unwrap().pop()` 会让 guard 活到整个 `if` 结束 → 先 `let item = list.lock()…pop()` 再 `if let` |
| 3 | **忽略虚假唤醒** | `park` / `condvar::wait` 必须放在 **`loop`/`while` 里反复检查条件**，不能单独 `if` |
| 4 | **`Rc`/`RefCell` 跨线程** | 报 `Send` not implemented → 换 **`Arc` + `Mutex`/`RwLock`** |

## Summary（本章小结）

- 程序由多线程组成；**主线程 `main` 返回即退出整个进程**（未 join 的子线程被终止）。  
- **共享/排他借用**在编译期杜绝安全代码中的数据竞争，避免 UB。  
- 跨线程共享：`Send`/`Sync` + `'static` / **`scope`** / **`Arc`** / `static` / `leak`。  
- **`UnsafeCell`** 开启内部可变性 → `Cell`/`RefCell` → 多线程 **`Atomics`**、`Mutex`、`RwLock`。  
- 等条件用 **park/unpark** 或 **`Condvar`+`Mutex`**，避免忙等；**必 `loop` 查条件**防虚假唤醒。

## 面试 / 笔试一句话（第一章）

**Rust 并发从线程共享内存出发，用共享/排他借用防数据竞争；跨线程用 `'static`/`Arc`/`scope` 解决所有权；用内部可变性 + `Mutex`/`Condvar`/原子类型安全共享可变状态；`Send`/`Sync` 标记线程安全边界。**
