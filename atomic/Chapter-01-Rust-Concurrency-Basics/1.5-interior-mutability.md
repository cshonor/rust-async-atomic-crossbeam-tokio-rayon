## 1.5 Interior Mutability（内部可变性）

> 书 §1.5 · 承接 [1.4 借用规则](./1.4.4-borrowing-rules.md) · 多线程版见 [1.7 Mutex / RwLock](./1.7-mutex-rwlock.md) · 原子见第 2 章

---

## 一、为什么需要内部可变性

普通规则：有 **`&T`（共享引用）** 就不能再有 **`&mut T`**。但有些 API 必须用 **`&self`**（不可变引用）却还要改内部状态——例如 `Counter::increment(&self)`。

**内部可变性（Interior Mutability）**：在类型**内部**提供「绕过表面不可变」的合法修改通道，由类型作者保证不 UB。

---

## 二、类型一览（单线程 → 多线程）

| 场景 | 类型 | 冲突时行为 |
|------|------|------------|
| 底层原语 | **`UnsafeCell<T>`** | 无检查；暴露 `*mut T`，由外层 / `unsafe` 保证 |
| 单线程、Copy 值 | **`Cell<T>`** | `get` / `set` / `take`；不能借内部引用 |
| 单线程、非 Copy | **`RefCell<T>`** | 运行时借用计数；违反规则 **panic** |
| 多线程、整型等 | **Atomics** | 硬件原子；第 2 章展开 |
| 多线程、任意 `T` | **`Mutex<T>` / `RwLock<T>`** | 冲突时**阻塞（sleep）**，不 panic |

---

## 三、`Cell<T>` 精读

**适用**：`T: Copy`（`i32`、`bool` 等）。通过 **`&Cell<T>`** 调用 `set` / `get`，**不**对外暴露 `&mut T`。

```rust
use std::cell::Cell;

let cell = Cell::new(5);
let r: &Cell<i32> = &cell;
r.set(10);
println!("{}", r.get()); // 10
```

### 典型模式：`&self` 里改字段

```rust
use std::cell::Cell;

struct Counter {
    count: Cell<u32>,
}

impl Counter {
    fn increment(&self) {
        self.count.set(self.count.get() + 1);
    }
}

let c = Counter { count: Cell::new(0) };
let r1 = &c;
let r2 = &c; // 多个 &Counter 可共存
r1.increment();
r2.increment();
```

仓库对应：Demo `demo_cell_solve_borrow_conflict`

### `take`

`take()` 拿走内部值，原位填 **`T::default()`**（`i32` 为 0）。

---

## 四、`RefCell<T>` 精读

**适用**：非 Copy 类型（`String`、`Vec` 等）。运行时跟踪借用：

- `borrow()` → `Ref<T>`（多个共享读 OK）
- `borrow_mut()` → `RefMut<T>`（独占写；与任何借用互斥）

```rust
use std::cell::RefCell;

let rc = RefCell::new(String::from("hello"));
{
    let mut s = rc.borrow_mut();
    s.push_str(" world");
}
println!("{}", rc.borrow());
```

违反规则（例如同时两个 `borrow_mut`）→ **panic**，不是 UB。

仓库对应：[1.5-interior-mutability-cell-refcell-demo.rs](./1.5-interior-mutability/1.5-interior-mutability-cell-refcell-demo.rs)

### 对照：`Cell` vs `RefCell`

| | **`Cell<T>`** | **`RefCell<T>`** |
|---|---------------|------------------|
| `T` 约束 | `Copy` | 任意 |
| 访问方式 | 复制 / 整体替换 | 借 `Ref` / `RefMut` |
| 运行时开销 | 无 | 借用计数 |
| 跨线程 | ❌ 非 `Sync` | ❌ 非 `Sync` |

---

## 五、`UnsafeCell<T>` 与多线程逃生舱

所有内部可变性的底层是 **`UnsafeCell`**：把 `&T` 转成可写的 `*mut T`，**无**安全检查。

多线程场景：

| 单线程组合 | 多线程组合 |
|------------|------------|
| `Rc<RefCell<T>>` | **`Arc<Mutex<T>>`** |
| `Rc<Cell<T>>`（少见） | **`Arc<RwLock<T>>`**、原子类型 |

> **`RefCell` 不能跨线程**：运行时借用计数非原子，多线程并发调用会数据竞争。

---

## 六、对照：panic vs sleep

| | **`RefCell`** | **`Mutex`** |
|---|---------------|-------------|
| 环境 | 单线程 | 多线程 |
| 冲突 | panic（程序员错误） | 阻塞等待 |
| 语义 | 「同一时刻只能一种借用」 | 「同一时刻只有一个线程持锁」 |

---

## 七、新手易错

1. **用 `RefCell` 跨线程**：编译不过；换 `Mutex`。
2. **长时间持有 `RefMut`**：阻塞同线程内其他 `borrow`，逻辑死锁式卡住。
3. **以为 `Cell` 能借引用**：只能 `get` 复制或 `set` 整体替换。
4. **内部可变性 = 可以乱写**：仍须遵守类型自己的不变量；只是把检查挪到运行时或锁里。
