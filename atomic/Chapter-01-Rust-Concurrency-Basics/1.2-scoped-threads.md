## 1.2 Scoped Threads（作用域线程）

> 书 §1.2 · 承接 [1.1 spawn / `'static`](./1.1-threads-in-rust.md)（[1.1.1](./1.1.1-spawn-join-basics.md) · [1.1.2 JoinHandle](./1.1.2-join-handle.md)）· 跨线程长期共享见 [1.3 Arc](./1.3-shared-ownership.md)

---

## 一、为什么需要 `thread::scope`

[1.1](./1.1-threads-in-rust.md) 里 `thread::spawn` 要求闭包 **`Send + 'static`**：子线程可能比创建它的栈帧活得更久，因此**不能借用**主线程（或任意调用栈）上的局部变量，只能 `move` 所有权进去。

常见痛点：

1. 只想并行处理**一块临时数组**，用完就丢——`spawn` 却逼你把 `Vec` **整份 move** 进子线程，或提前包一层 `Arc`。
2. 子线程数量固定、且**一定在函数返回前结束**——手动 `join` 每个 `JoinHandle` 繁琐，漏 join 还可能被强杀。
3. 希望编译器**替你保证**：「所有子线程跑完之前，被借用的局部变量不会被销毁」。

**`thread::scope`**（Rust **1.63+**）就是标准库给的答案：在**闭包作用域**里开子线程，允许**安全借用** scope **之外、仍在存活**的局部数据；scope 结束时**自动 join** 全部子线程。

---

## 二、两种线程：有界 `thread::scope` vs 无界 `thread::spawn`

Rust 标准库里创建 OS 线程主要有两条路：**有界作用域**的 `thread::scope` 与**无界**的 `thread::spawn`。二者在「能否借局部变量」「要不要手动 join」上差别很大。

### 1. 有界作用域线程 `thread::scope`（稳定 API，1.63+）

```rust
use std::thread;

fn main() {
    thread::scope(|s| {
        // s.spawn 返回 ScopedJoinHandle<'scope, T>
        let h = s.spawn(|| 1 + 1);
        let _ = h; // 不显式 join 也行——见下文「自动 join」
    });
    // 离开 scope 闭包时，标准库会对尚未 join 的 handle 批量 join
}
```

**核心特性**：

1. 在 `scope` 闭包里用 **`s.spawn()`** 开子线程；
2. **scope 闭包执行完毕时，会自动隐式 join 所有尚未 join 的子线程**，不必像 `spawn` 那样逐个手动 `.join()`；
3. 可**安全借用** scope 外的局部变量，通常**不必 `move`**；
4. 仍可**手动提前 `.join()`** 取返回值：

```rust
thread::scope(|s| {
    let h = s.spawn(|| 2);
    let res = h.join().unwrap(); // 手动提前 join
    println!("{res}");
});
```

> **易错**：`ScopedJoinHandle` **不能逃出** scope（不能 `push` 进 scope 外的 `Vec` 再慢慢 join）——类型系统保证子线程寿命 ≤ scope。

### 2. 普通无界线程 `thread::spawn`

```rust
use std::thread;

let h = thread::spawn(move || 1 + 1);
// 没有自动 join；必须手动 join，否则 main 可能先退出、子线程被强杀
h.join().unwrap();
```

- 返回 **`JoinHandle<T>`**（详见 [1.1.2](./1.1.2-join-handle.md)），**不会自动 join**；
- 闭包须 **`Send + 'static`**，捕获栈上局部变量须 **`move`** 所有权，不能直接借用。

### 3. 借用局部变量：`scope` 典型用法

```rust
use std::thread;

fn main() {
    let num = 50;
    let vec = vec![1, 2, 3];

    thread::scope(|s| {
        s.spawn(|| {
            println!("{num}, {:?}", vec); // 借用 scope 外变量，无需 move
        });
    });
    println!("scope 结束，vec 仍可用: {:?}", vec);
}
```

**补充规则**：

1. **`thread::scope` 会阻塞**调用它的线程，直到 scope 内全部子线程结束；
2. scope 闭包**里面**新定义的变量，若要在 `s.spawn` 里用，通常仍要 **`move`**；
3. 多个 `s.spawn` 的**执行顺序由 OS 调度**，打印顺序不保证（见 Demo 示例 2）。

## 三、`.join()` 与 scope 自动 join：别混成一件事

| 概念 | 是什么 | 谁有 |
|------|--------|------|
| **`.join()` 方法** | 阻塞**当前**线程，等待目标子线程结束，取 `Result<T, _>` / 传播 panic | `JoinHandle` 与 `ScopedJoinHandle` **都有** |
| **scope 自动 join** | `thread::scope` 闭包**走完后**，标准库对**尚未 join** 的 `ScopedJoinHandle` **批量 join** | **仅** `thread::scope` |

### 1. `.join()` 方法（两种句柄通用）

```rust
// 普通 spawn
let h = thread::spawn(move || 42);
h.join().unwrap(); // JoinHandle::join()

// scope 内
thread::scope(|s| {
    let h = s.spawn(|| 42);
    h.join().unwrap(); // ScopedJoinHandle::join() — 语义类似，生命周期绑在 'scope
});
```

作用：阻塞 caller、回收 OS 线程资源、取回返回值或捕获 panic（[1.1.2 §二](./1.1.2-join-handle.md#二err-类型三层拆解-boxdyn-any--send--static)）。

### 2. scope 的自动 join（语法糖，不是第三种 API）

这是 **`thread::scope` 独有**的保障机制：**程序流离开 scope 闭包**时，运行库保证所有 `s.spawn` 创建的子线程已结束，再销毁被借用的局部变量。

- **不等于**「不需要 `.join()` 这个概念」——自动 join 本质上就是在 scope 末尾替你调用了未处理的 handle 的 join；
- **你仍可以**在 scope 内**提前** `.join()` 拿返回值，不必等到闭包最后一行；
- **`thread::spawn` 完全没有**这层自动 join：drop 未 join 的 `JoinHandle` → 线程 **detach**；`main` 直接退出 → 子线程可能被强杀（[1.1.2 §四](./1.1.2-join-handle.md#四不用-join-会怎样)）。

**背诵**：

1. 单词是 **Join**，不是 Enjoy；
2. `thread::scope`：**离开 scope 自动 join 全部** + 可选手动 `.join()`；
3. `thread::spawn`：**必须**手动 `.join()`（或承担 detach / 被强杀风险）。

## ScopedJoinHandle\<T\> 精读（`s.spawn` 返回值）

**一句话**：`s.spawn(闭包)` → 返回 **`ScopedJoinHandle<'scope, T>`**，语义类似 [1.1.2 的 `JoinHandle<T>`](./1.1.2-join-handle.md)，但生命周期绑在 **`'scope`** 上。

```rust
use std::thread;

fn main() {
    let result = thread::scope(|s| {
        let h = s.spawn(|| 10 + 20); // ScopedJoinHandle<'_, i32>
        h.join().unwrap()             // 也可不显式 join，scope 结束时会 join
    });
    println!("{result}");
}
```

### 1. 与 `JoinHandle` 的异同

| | **`thread::spawn`** | **`Scope::spawn`（scope 内）** |
|---|---------------------|--------------------------------|
| 句柄 | `JoinHandle<T>` | `ScopedJoinHandle<'scope, T>` |
| 闭包约束 | `FnOnce() -> T + Send + 'static` | `FnOnce() -> T + Send + 'scope` |
| 借用局部变量 | ❌ 不行（须 `'static`） | ✅ 可借 **`'scope` 内** 的数据 |
| 未 join 就离开 | drop → detached，可能泄漏线程 | **编译期禁止**：不能带着 handle 逃出 scope |
| 等待 | `.join()` 或 drop handle | scope 结束自动 join；也可手动 `.join()` |

### 2. 类型拆解（对比记忆）

```rust
// 普通 spawn
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T + Send + 'static,
    T: Send + 'static,

// scope 内 spawn（示意）
fn spawn<'scope, F, T>(&'scope self, f: F) -> ScopedJoinHandle<'scope, T>
where
    F: FnOnce() -> T + Send + 'scope,
    T: Send + 'scope,
```

关键差别在 **`'static` → `'scope`**：子线程只能活在这个 scope 里，因此可以借用「只要 scope 还在就不能被销毁」的栈上数据。

### 3. 数据竞争仍由编译器拦截

scope **不是**「随便共享可变数据」：

- 多个子线程**只读**借用同一 `&T` → 通常可以；
- 任一子线程需要 **`&mut T`** → 编译器保证同一时刻只有一个活跃的可变借用 → **编译期防数据竞争**（详细规则见 [1.4 借用与数据竞争](./1.4-borrowing-data-races.md)）。

## 四、scope 内外的变量规则

| 变量位置 | 在 `s.spawn` 里怎么用 | scope 外还能用吗 |
|----------|----------------------|------------------|
| scope **上面**（闭包外、调用前定义） | 直接借用，**不必 move** | ✅ scope 结束后仍可用（若没被 move 进某线程） |
| scope **内部**（闭包 `{ }` 里定义） | 通常 **`move`** 进子线程 | ❌ 不能把 `inside_scope` 当普通变量拿到外面 |
| scope **返回值** | 闭包最后一行表达式 | ✅ `let x = thread::scope(\|s\| { … })` |

```rust
use std::thread;

fn main() {
    let before = 10;

    let result = thread::scope(|s| {
        let inside = 20;

        s.spawn(|| println!("借 before: {before}"));

        s.spawn(move || println!("move inside: {inside}"));

        before + inside // scope 闭包返回值
    });

    println!("{result:?}");
    // println!("{inside}"); // 编译错误：inside 作用域仅在 scope 闭包内
}
```

## 五、如何把 scope 内的结果带到外面

子线程若在 scope **内部**创建，其栈上局部变量**不能**直接在外面访问。常用三种出路：

### 1. scope 闭包返回值（最简单）

```rust
let sum = thread::scope(|s| {
    let nums = vec![1, 2, 3, 4, 5];
    let total: i32 = nums.iter().sum();
    s.spawn(move || println!("子线程: sum = {total}"));
    total // 返回给 scope 外
});
```

### 2. 在 scope 外创建 `Arc<Mutex<T>>`（多线程汇总）

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let acc = Arc::new(Mutex::new(0));

thread::scope(|s| {
    for i in 1..=5 {
        let acc = Arc::clone(&acc);
        s.spawn(move || {
            *acc.lock().unwrap() += i;
        });
    }
});

println!("{}", *acc.lock().unwrap());
```

> `Arc` 本身 `'static` 友好；scope 只解决「**借用栈上数据**」的问题，**长期跨线程共享可变状态**仍靠 [1.3](./1.3-shared-ownership.md) / [1.7 Mutex](./1.7-mutex-rwlock.md)。

### 3. 数据本来就在 scope 外，子线程只负责写

把要修改的结构定义在 `thread::scope` **之前**，子线程里通过 `Mutex` / 原子类型更新；scope 结束后读最终值（同 Demo 示例 4）。

## 六、对照表：`thread::spawn` vs `thread::scope`

> 有界 / 无界概念见 [§二](#二两种线程有界-threadscope-vs-无界-threadspawn)；`.join()` vs 自动 join 见 [§三](#三join-方法与-scope-自动-join别混成一件事)。

| | **`thread::spawn`** | **`thread::scope`** |
|---|---------------------|---------------------|
| 线程寿命 | 与进程同级，可超过创建者栈帧 | **限于 scope 块**，结束必 join |
| 借用局部变量 | ❌ 须 `'static` / `move` | ✅ 可借 `'scope` 内数据 |
| 等待方式 | 手动 `.join()` 每个 handle | scope 结束**自动** join 全部 |
| handle 逃逸 | 可以（也易漏 join） | **不可**把 `ScopedJoinHandle` 带出 scope |
| 典型场景 | 后台任务、与 caller 生命周期解耦 | 短生命周期并行、map-reduce 式批处理 |
| 稳定版本 | 1.0 起 | **1.63** 起 |

```rust
use std::thread;

let vec = vec![1, 2, 3];

// spawn：必须 move，vec 所有权进子线程
let h = thread::spawn(move || println!("{:?}", vec));
h.join().unwrap();
// vec 此处已不可用

let vec2 = vec![4, 5, 6];
thread::scope(|s| {
    s.spawn(|| println!("{:?}", vec2)); // 借用即可
});
// vec2 仍可用
```

## 七、历史：Leakpocalypse 与 Rust 1.63

Rust **1.0 之前**曾提供基于 **`JoinGuard` + `Drop` 自动 join** 的 `scoped` 线程 API：guard 离开作用域时在 `Drop` 里 join 子线程，看起来能安全借用栈上数据。

**Leakpocalypse**（社区对这次设计失败的称呼）：

1. `mem::forget(guard)`、**循环引用**等可以让 guard **永不 Drop**；
2. 子线程继续跑，却**不再被 join**，仍借用已失效的栈内存 → **Unsound**（安全 API 在 leak 下失效）；
3. 该 API 在 **1.0 前被移除**。

**准则**：**安全 API 不能假设「对象一定会被 Drop」**。

直到 **Rust 1.63**，标准库用 **`thread::scope` 闭包** 重新实现：

- 子线程 handle **不能逃出** scope（类型系统保证）；
- scope 函数**同步阻塞**到全部 join 完成，**不依赖 Drop 做安全边界**；
- 借用规则由 **`'scope`** 生命周期参数编码，而非「希望用户会 drop guard」。

## 八、新手易错

1. **把 Enjoy 当 Join**：正确是 **`JoinHandle` / `.join()`**（见 [1.1.2 §五](./1.1.2-join-handle.md#五两个易混点)）。
2. **以为 scope = 可以随意并发写同一变量**：没有 `Mutex` / 原子类型时，多个 `&mut` 仍会被编译器拒绝。
3. **在 scope 里 `sleep` 很久却以为「不阻塞主线程」**：`thread::scope` **会阻塞调用它的线程**（通常就是主线程），只是帮你自动 join。
4. **纠结子线程打印顺序**：同一 scope 里多个 `s.spawn` 的执行顺序**不确定**，调试请加线程名或序号。
5. **scope 能借局部变量，就不用 `Arc` 了？** 仅当**所有线程一定在 scope 内结束**且只需**借用**时成立；线程要活得比函数更久 → 仍用 `spawn` + `Arc`（见 [1.3](./1.3-shared-ownership.md)）。
6. **把「自动 join」当成 spawn 也有**：只有 **`thread::scope`** 在闭包结束时批量 join；**`thread::spawn` 必须手动**（见 [§三](#三join-方法与-scope-自动-join别混成一件事)）。
