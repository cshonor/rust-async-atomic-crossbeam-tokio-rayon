## 一、为什么需要 `thread::scope`

[1.1](./1.1-threads-in-rust.md) 里 `thread::spawn` 要求闭包 **`Send + 'static`**：子线程可能比创建它的栈帧活得更久，因此**不能借用**主线程（或任意调用栈）上的局部变量，只能 `move` 所有权进去。

常见痛点：

1. 只想并行处理**一块临时数组**，用完就丢——`spawn` 却逼你把 `Vec` **整份 move** 进子线程，或提前包一层 `Arc`。
2. 子线程数量固定、且**一定在函数返回前结束**——手动 `join` 每个 `JoinHandle` 繁琐，漏 join 还可能被强杀。
3. 希望编译器**替你保证**：「所有子线程跑完之前，被借用的局部变量不会被销毁」。

**`thread::scope`**（Rust **1.63+**）就是标准库给的答案：在**闭包作用域**里开子线程，允许**安全借用** scope **之外、仍在存活**的局部数据；scope 结束时**自动 join** 全部子线程。

---

## 二、两种线程：有界 `thread::scope` vs 无界 `thread::spawn`

Rust 标准库里创建 OS 线程主要有两条路：**有界作用域**的 `thread::scope` 与**无界**的 `thread::spawn`。二者 API 相似（都叫 `spawn`），但**返回值类型、生命周期约束、join 行为**完全不同。

### 0. 两个 `spawn` 完整区分（带类型标注）

#### ① 全局：`std::thread::spawn`（无 scope 普通线程）

```rust
use std::thread;

// 返回：JoinHandle<T>
let handle: thread::JoinHandle<i32> = thread::spawn(move || 123);
handle.join().unwrap();
```

| 项 | 说明 |
|----|------|
| **返回类型** | `JoinHandle<T>`（[1.1.2](./1.1.2-join-handle.md)） |
| **闭包约束** | `Send + 'static`；捕获局部变量须 **`move`**，**不能借用**栈上临时数据 |
| **线程寿命** | 不受当前函数 / scope 限制，可活得比创建者更久 |
| **等待** | **不会**自动 join；须手动 `.join()`，否则 drop → **detach**，`main` 提前退出则可能强杀子线程 |

#### ② scope 内：`s.spawn()`（有界作用域线程）

```rust
use std::thread;

thread::scope(|s| {
    // s.spawn 返回 ScopedJoinHandle<'scope, T>
    let scoped_handle: thread::ScopedJoinHandle<'_, i32> = s.spawn(|| 123);
    let _ = scoped_handle; // 也可手动 scoped_handle.join().unwrap()
});
// 离开 scope：Scope 收尾批量 join 尚未 join 的 handle
```

| 项 | 说明 |
|----|------|
| **返回类型** | `ScopedJoinHandle<'scope, T>`，带生命周期 **`'scope`** |
| **闭包约束** | `Send + 'scope`；**可借用** scope 外、仍在存活的栈变量，通常**不必 move** |
| **线程寿命** | **锁在 scope 内**；handle **不能逃出** scope 闭包 |
| **等待** | scope 收尾**自动 join** 未处理的 handle；也可在 scope 内**手动** `.join()` |

> 口语里常把 `ScopedJoinHandle` 简称 scope 句柄；标准库全名是 **`ScopedJoinHandle`**，不是 `ScopeJoinHandle`。

### 1. 有界作用域线程 `thread::scope`（稳定 API，1.63+）

```rust
use std::thread;

fn main() {
    thread::scope(|s| {
        // s.spawn 返回 ScopedJoinHandle<'scope, T>
        let h = s.spawn(|| 1 + 1);
        let _ = h; // 不显式 join 也行——见下文「自动 join」
    });
    // 离开 scope 闭包时，标准库会对尚未 join 的 handle 批量 join
}
```

**核心特性**：

1. 在 `scope` 闭包里用 **`s.spawn()`** 开子线程；
2. **scope 闭包执行完毕时，会自动隐式 join 所有尚未 join 的子线程**，不必像 `spawn` 那样逐个手动 `.join()`；
3. 可**安全借用** scope 外的局部变量，通常**不必 `move`**；
4. 仍可**手动提前 `.join()`** 取返回值：

```rust
thread::scope(|s| {
    let h = s.spawn(|| 2);
    let res = h.join().unwrap(); // 手动提前 join
    println!("{res}");
});
```

> **易错**：`ScopedJoinHandle` **不能逃出** scope（不能 `push` 进 scope 外的 `Vec` 再慢慢 join）——类型系统保证子线程寿命 ≤ scope。

### 2. 普通无界线程 `thread::spawn`

```rust
use std::thread;

let h = thread::spawn(move || 1 + 1);
// 没有自动 join；必须手动 join，否则 main 可能先退出、子线程被强杀
h.join().unwrap();
```

- 返回 **`JoinHandle<T>`**（详见 [1.1.2](./1.1.2-join-handle.md)），**不会自动 join**；
- 闭包须 **`Send + 'static`**，捕获栈上局部变量须 **`move`** 所有权，不能直接借用。

### 3. 借用局部变量：`scope` 典型用法

```rust
use std::thread;

fn main() {
    let num = 50;
    let vec = vec![1, 2, 3];

    thread::scope(|s| {
        s.spawn(|| {
            println!("{num}, {:?}", vec); // 借用 scope 外变量，无需 move
        });
    });
    println!("scope 结束，vec 仍可用: {:?}", vec);
}
```

**补充规则**：

1. **`thread::scope` 会阻塞**调用它的线程，直到 scope 内全部子线程结束；
2. scope 闭包**里面**新定义的变量，若要在 `s.spawn` 里用，通常仍要 **`move`**；
3. 多个 `s.spawn` 的**执行顺序由 OS 调度**，打印顺序不保证（见 Demo 示例 2）。

仓库对应：[1.2-scoped-threads-demo.rs](./1.2-scoped-threads/1.2-scoped-threads-demo.rs)（示例 1、2）

## 三、`.join()` 与 scope 自动 join：别混成一件事

| 概念 | 是什么 | 谁有 |
|------|--------|------|
| **`.join()` 方法** | 阻塞**当前**线程，等待目标子线程结束，取 `Result<T, _>` / 传播 panic | `JoinHandle` 与 `ScopedJoinHandle` **都有** |
| **scope 自动 join** | `thread::scope` 闭包**走完后**，标准库对**尚未 join** 的 `ScopedJoinHandle` **批量 join** | **仅** `thread::scope` |

### 1. `.join()` 方法（两种句柄通用）

```rust
// 普通 spawn
let h = thread::spawn(move || 42);
h.join().unwrap(); // JoinHandle::join()

// scope 内
thread::scope(|s| {
    let h = s.spawn(|| 42);
    h.join().unwrap(); // ScopedJoinHandle::join() — 语义类似，生命周期绑在 'scope
});
```

作用：阻塞 caller、回收 OS 线程资源、取回返回值或捕获 panic（[1.1.2 §二](./1.1.2-join-handle.md#二err-类型三层拆解-boxdyn-any--send--static)）。

### 2. scope 的自动 join（语法糖，不是第三种 API）

这是 **`thread::scope` 独有**的保障机制：**程序流离开 scope 闭包**时，运行库保证所有 `s.spawn` 创建的子线程已结束，再销毁被借用的局部变量。

- **不等于**「不需要 `.join()` 这个概念」——自动 join 本质上就是在 scope 末尾替你调用了未处理的 handle 的 join；
- **你仍可以**在 scope 内**提前** `.join()` 拿返回值，不必等到闭包最后一行；
- **`thread::spawn` 完全没有**这层自动 join：drop 未 join 的 `JoinHandle` → 线程 **detach**；`main` 直接退出 → 子线程可能被强杀（[1.1.2 §四](./1.1.2-join-handle.md#四不用-join-会怎样)）。

**背诵**：

1. 单词是 **Join**，不是 Enjoy；
2. `thread::scope`：**离开 scope 自动 join 全部** + 可选手动 `.join()`；
3. `thread::spawn`：**必须**手动 `.join()`（或承担 detach / 被强杀风险）。

### 3. 分层拆解：自动 join 做了什么？是不是封装系统调用？

先分两层：**Rust 标准库逻辑** 与 **OS 系统调用**。

#### （1）第一层：scope 自动 join = std 库逻辑，不是内核「自动行为」

`thread::scope` 内部会登记每次 `s.spawn` 返回的 **`ScopedJoinHandle`**。当 scope 闭包结束、内部的 **`Scope` 对象析构**时，标准库会**遍历尚未手动 join 的句柄，逐个调用 `.join()`**。

**伪代码（心智模型，非源码逐行对应）**：

```rust
struct Scope {
    handles: Vec<ScopedJoinHandle<()>>,
}

impl Drop for Scope {
    fn drop(&mut self) {
        for h in self.handles.drain(..) {
            let _ = h.join(); // 自动 join：与你手写 h.join() 走同一条路
        }
    }
}
```

要点：

- 「自动阻塞」的**触发**来自 std 在 scope 收尾时的**库逻辑**（常见实现是 `Scope` 析构里批量 join）；
- **操作系统不知道** Rust 的 `Scope`、`Drop`、作用域——这层是上层封装；
- **借用栈上数据的安全性**不靠「Drop 一定执行」（Leakpocalypse 教训），而靠 **`'scope` + handle 不能逃出 scope**（见 [§八](#八历史leakpocalypse-与-rust-163)）。

#### （2）第二层：`.join()` 内部才下沉到 OS 阻塞 API

无论**手动** `h.join()`，还是 **scope 收尾自动**调用的 `h.join()`，标准库底层最终都会走到跨平台线程等待原语（[1.1.2 §六](./1.1.2-join-handle.md#六底层原理os--标准库--join)）：

| 平台 | 典型底层 |
|------|----------|
| Linux / Unix | `pthread_join()`（POSIX；内核侧常经 futex 等机制阻塞） |
| Windows | `WaitForSingleObject()` 等待线程内核句柄 |

**流程串联**：

```text
离开 scope 闭包
  → Scope 析构 / std 批量 join
  → ScopedJoinHandle::join()
  → std::thread 跨平台封装
  → pthread_join / WaitForSingleObject
  → 内核阻塞当前线程，直到目标子线程退出
```

#### （3）三个常见疑问

1. **「自动阻塞」不是 OS 在线程作用域结束时自动做的**  
   普通 `thread::spawn` 无 scope：`main` 直接退出时子线程可能被强杀——说明 **OS 不会替你 join**。

2. **「自动」= Rust 帮你调了 `.join()`，不是第三种等待 API**  
   执行链路与手写 `join` **一致**，最终都会下沉到**阻塞型系统调用**。

3. **阻塞发生在哪条线程上？**  
   scope 收尾触发 join 时，**当前正在执行 scope 闭包的那条线程**（通常是主线程）会**逐个阻塞**等待未完成的子线程；全部结束后，`Scope` 析构完成，控制流才走出 `thread::scope(...)` 块。

#### （4）手动 join vs 自动 join：底层无差别

```rust
use std::thread;

// 场景 1：手动 join，显式阻塞
thread::scope(|s| {
    let h = s.spawn(|| {});
    h.join().unwrap(); // 你触发 → 同样走 OS 等待 API
});

// 场景 2：自动 join，隐式阻塞
thread::scope(|s| {
    s.spawn(|| {});
}); // Scope 收尾替你 join → OS 等待 API 相同
```

唯一区别：**谁调用 `.join()`**——你手写，还是 `Scope` 收尾自动调用。

#### （5）scope 自动 join 时，`Result<T, _>` 怎么处理？

Scope 收尾批量 `.join()` 时，标准库**不会把 `Ok(T)` 交给你**——返回值被丢弃：

| 子线程结局 | 自动 join 行为 |
|------------|----------------|
| **正常返回 `T`** | join 成功，**`T` 被丢弃**；要拿值须 scope 内**手动** `.join()` |
| **panic** | join 得到 **`Err`** → std **继续 panic**（不会静默吞掉） |

```rust
use std::thread;

// 要拿到 T：必须手动 join
thread::scope(|s| {
    let handle = s.spawn(|| 100);
    let val = handle.join().unwrap(); // T = 100
    println!("{val}");
});

// 自动 join：Ok(T) 丢弃；若子线程 panic → 整个程序 panic
thread::scope(|s| {
    s.spawn(|| 100); // 离开 scope 时 join，你看不到 100
});
```

与 [1.1.2 §二 `T` vs `Result`](#joinhandlet-的-t-vs-join-的-result两个独立层次) 对照：**自动 join 只保证「等线程跑完 + panic 不静默」**，不替你保存业务返回值 **`T`**。

## ScopedJoinHandle\<T\> 精读（`s.spawn` 返回值）

**一句话**：`s.spawn(闭包)` → 返回 **`ScopedJoinHandle<'scope, T>`**，语义类似 [1.1.2 的 `JoinHandle<T>`](./1.1.2-join-handle.md)，但生命周期绑在 **`'scope`** 上。

```rust
use std::thread;

fn main() {
    let result = thread::scope(|s| {
        let h = s.spawn(|| 10 + 20); // ScopedJoinHandle<'_, i32>
        h.join().unwrap()             // 也可不显式 join，scope 结束时会 join
    });
    println!("{result}");
}
```

### 1. 与 `JoinHandle` 的异同

| | **`thread::spawn`** | **`Scope::spawn`（scope 内）** |
|---|---------------------|--------------------------------|
| 句柄 | `JoinHandle<T>` | `ScopedJoinHandle<'scope, T>` |
| 闭包约束 | `FnOnce() -> T + Send + 'static` | `FnOnce() -> T + Send + 'scope` |
| 借用局部变量 | ❌ 不行（须 `'static`） | ✅ 可借 **`'scope` 内** 的数据 |
| 未 join 就离开 | drop → detached，可能泄漏线程 | **编译期禁止**：不能带着 handle 逃出 scope |
| 等待 | `.join()` 或 drop handle | scope 结束自动 join；也可手动 `.join()` |

### 2. 类型拆解（对比记忆）

```rust
// 普通 spawn
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T + Send + 'static,
    T: Send + 'static,

// scope 内 spawn（示意）
fn spawn<'scope, F, T>(&'scope self, f: F) -> ScopedJoinHandle<'scope, T>
where
    F: FnOnce() -> T + Send + 'scope,
    T: Send + 'scope,
```

关键差别在 **`'static` → `'scope`**：子线程只能活在这个 scope 里，因此可以借用「只要 scope 还在就不能被销毁」的栈上数据。

### 2.1 `s.spawn` 签名（逐条拆解）

> **命名对照（教材 vs 标准库）**：部分讲解把闭包约束写成 **`F: 'env`**、句柄写成 **`ScopeJoinHandle<'env, T>`**（把 `'env` 当「scope 外栈变量的生命周期」）。标准库实际写法是 **`F: 'scope`**、**`ScopedJoinHandle<'scope, T>`**；`'env` 出现在 **`Scope<'scope, 'env>`** 上，表示**外部环境须活得比 `'scope` 长**（`'env: 'scope`）。下文按**标准库**名称讲解。

```rust
impl<'scope, 'env: 'scope> Scope<'scope, 'env> {
    pub fn spawn<F, T>(&self, f: F) -> ScopedJoinHandle<'scope, T>
    where
        F: FnOnce() -> T + Send + 'scope,
        T: Send + 'scope,
}
```

| # | 约束 | 与普通 `spawn` 的差别 |
|---|------|----------------------|
| **1** | `F: FnOnce() -> T` | 相同：一次性线程入口，产出 `T` |
| **2** | `F: Send` | 相同：闭包须 **move 到子线程** |
| **3** | `F: 'scope` | **代替 `F: 'static`**：闭包可借用 **scope 存活期内** 的外部栈数据 |
| **4** | `T: Send + 'scope` | **不要 `'static`**，但要 **`'scope`**（口语有时简写「仅 Send」；标准库仍要求 **`T: 'scope`**，返回值不能比 scope 活得更久还带借用） |

| 教材常见写法 | 标准库写法 | 含义 |
|--------------|------------|------|
| `F: 'env` | **`F: 'scope`** | 闭包可借 **scope 存活期内** 的数据，代替 **`F: 'static`** |
| `ScopeJoinHandle<'env, T>` | **`ScopedJoinHandle<'scope, T>`** | 句柄不能逃出 scope |
| `T: Send`（仅 Send） | **`T: Send + 'scope`** | 返回值可跨线程传回，且寿命 ≤ scope |

#### 为什么 `'scope` 能借局部变量？

标准库保证：**离开 scope 前 join 全部子线程** → 被借用的外部变量生命周期 **≥** 所有子线程运行期 → 不会出现悬垂引用。完整签名见 [§四](#四参数-s-是什么从哪来)。

#### `Send` 两个 spawn 都要？

**`Send`** = 该类型的所有权可以**安全地从一线程转移到另一线程**。只要有「把闭包 move 给新线程」，就要求 **`F: Send`**，与有界 / 无界无关。常见 **非 Send**：`Rc<T>`、`*const T` / `*mut T`（默认）、`&mut T`（在多数跨线程场景）。

### 2.2 最简示例对比

**scope：允许借用（`F: 'scope`）**

```rust
let msg = "hello"; // 局部生命周期
thread::scope(|s| {
    s.spawn(|| println!("{msg}")); // 借 msg，不必 move
});
```

**普通 spawn：须 move（`F: 'static`）**

```rust
let msg = "hello".to_string();
let h = thread::spawn(move || println!("{msg}"));
h.join().unwrap();
```

**scope 里也可以 `move`（不冲突）**

```rust
let s = String::from("test");
thread::scope(|sc| {
    sc.spawn(move || println!("{s}")); // move 进闭包，仍满足 'scope
});
```

## 两段 spawn 泛型约束对照

> 普通 `thread::spawn` 逐条见 [1.1.3 §一](./1.1.3-send-static-spawn.md#一spawn-完整签名逐条拆解)。

| 约束点 | `thread::spawn` | `s.spawn`（scope 内） |
|--------|-----------------|------------------------|
| 闭包特征 | `FnOnce() -> T` | 同左 |
| 跨线程 move | **`F: Send`** | **`F: Send`** |
| 闭包生命周期 | **`F: 'static`** | **`F: 'scope`**（可借局部栈变量） |
| 能否借栈引用 | ❌ 禁止，须 **move** | ✅ 允许，通常不必 move |
| 返回值 `T` | **`Send + 'static`** | **`Send + 'scope`**（不要 `'static`） |
| 返回句柄 | `JoinHandle<T>` | `ScopedJoinHandle<'scope, T>` |
| 自动 join | ❌ | ✅ scope 收尾批量 join |

**为什么 scope 不用 `'static`？**  
Scope **强制等待**：所有子线程在 scope 结束前 join → 外部栈变量一定活得比子线程久 → 编译器用 **`'scope`** 绑定即可，不必抬到全程序 `'static`。

## `'static` vs `'scope`：生命周期深拆

> 普通 `spawn` 的 `'static` 见 [1.1.3 §三](./1.1.3-send-static-spawn.md#三为什么必须-static)。

### 1. 一句话对比

| | `thread::spawn` | `s.spawn` |
|---|-----------------|-----------|
| 线程寿命 | 可能**活过**创建者栈帧 | **一定死在** scope 结束前 |
| 生命周期约束 | **`F: 'static`**，**`T: Send + 'static`** | **`F: 'scope`**，**`T: Send + 'scope`** |
| 捕获局部变量 | ❌ 禁止借用；须 **move** 或 `'static` 数据 | ✅ 可**直接借用**外部栈变量 |

### 2. `'scope` 从哪来？`thread::scope` 签名

```rust
pub fn scope<'env, F, T>(f: F) -> T
where
    F: for<'scope> FnOnce(&'scope Scope<'scope, 'env>) -> T,
```

- **`'env`**：scope **外面**那层环境（例如 `fn main` 里的局部变量）；
- **`'scope`**：scope **闭包执行期间**——所有 `s.spawn` 子线程**必须在此结束前 join**；
- **`ScopedJoinHandle<'scope, T>`** 把句柄和返回值绑在 **`'scope`** 上，**不能逃出**闭包。

因此编译器能证明：被借用的栈变量（如外面的 `num`）生命周期 **≥ `'scope` ≥ 所有子线程** → 不会悬垂。

```rust
let num = 10; // 栈变量，生命周期覆盖整个 scope 调用
thread::scope(|s| {
    s.spawn(|| println!("{num}")); // 借 &num，'scope 由 Scope 约束
});
// 到这里：全部子线程已 join，num 才安全销毁
```

**一句话**：**`s.spawn` — 线程一定死在 scope 结束前 → 绑定局部 `'scope`，允许借栈引用。**

### 3. 生命周期标注 ≠ 传入的一定是引用

生命周期泛型（`'static` / `'scope`）是**安全检查规则**：约束「**若存在借用，被借的数据须活够久**」——**不**表示闭包里只能传引用。

#### （1）传引用（无 `move`，scope 典型）

```rust
let s = String::from("hello");
thread::scope(|sc| {
    sc.spawn(|| println!("{s}")); // 闭包捕获 &String，生命周期 'scope
});
```

只借、不转移所有权；安全靠 scope **自动 join** + `'scope` 证明。

#### （2）传所有权（`move`，两种 spawn 都常见）

```rust
let s = String::from("hello");
thread::scope(|sc| {
    sc.spawn(move || println!("{s}")); // 无 &，String 所有权进子线程
});
```

- **`move`** 后闭包内**没有**对外部变量的引用，仍满足 **`'scope`**（或普通 spawn 的 **`'static`**）；
- **`thread::spawn` 绝大多数场景**都是这种「所有权转移、无引用」——因为**不允许借栈**。

#### （3）区分记忆

| 概念 | 说明 |
|------|------|
| **`JoinHandle<T>` / `ScopedJoinHandle<'scope, T>` 的 `T`** | 可以是 **`String`、`i32`**（owned），也可以是 **`&'scope i32`**（借用） |
| **何时产生引用？** | **不写 `move`、直接捕获外部变量** → 闭包往往捕获 **`&T`** |
| **何时无引用？** | **`move`** → 转移所有权；普通 spawn 靠此满足 **`'static`** |

### 4. 补充细节（背诵）

1. **`'static`**：最长生命周期标注，**不是类型**；spawn 侧表示「不能依赖短栈借用」。  
2. **`'scope`**：**局部临时**生命周期，只覆盖 scope 闭包执行阶段。  
3. **生命周期 = 规则**，你可以选 **借用（无 move）** 或 **转移所有权（move）**；scope 两种都合法，普通 spawn 实际上只能后者（或 `'static` 数据）。  
4. 普通 spawn **没有** scope 的强制 join 保护 → **彻底禁用**借局部栈，只能 **move** 凑 **`'static`**。

---

### 3. 数据竞争仍由编译器拦截

scope **不是**「随便共享可变数据」：

- 多个子线程**只读**借用同一 `&T` → 通常可以；
- 任一子线程需要 **`&mut T`** → 编译器保证同一时刻只有一个活跃的可变借用 → **编译期防数据竞争**（详细规则见 [1.4 借用与数据竞争](./1.4-borrowing-data-races.md)）。

### 4. `JoinHandle` vs `ScopedJoinHandle`：四条核心差别

1. **生命周期绑定**
   - **`JoinHandle<T>`**：无 `'scope` 参数；句柄可存进 `Vec`、从函数**返回**、活得比创建它的栈帧更久；
   - **`ScopedJoinHandle<'scope, T>`**：绑定 scope 生命周期 **`'scope`**，**只能在 scope 闭包内**使用，编译器禁止带出闭包。

2. **安全规则（最大区别）**

   普通 `thread::spawn` **强制 move / `'static`**，不允许借栈：

   ```rust
   let x = 10;
   thread::spawn(|| println!("{x}")); // 编译错误：不能借用 x
   ```

   scope 的 `s.spawn` **允许借用** scope 外变量：

   ```rust
   let x = 10;
   thread::scope(|s| {
       s.spawn(|| println!("{x}")); // OK：'scope 保证 x 不会先于子线程销毁
   });
   ```

   原理：类型系统 + `'scope` 证明「所有子线程在 scope 结束前结束 → 被借用的 `x` 不会提前 drop」。

3. **未 join 就「丢」句柄时**
   - **`JoinHandle`**：drop 且未 join → 线程 **detach**；`main` 直接结束 → 子线程可能被 OS 强杀（[1.1.2 §四](./1.1.2-join-handle.md#四不用-join-会怎样)）；
   - **`ScopedJoinHandle`**：不能逃出 scope；scope 收尾时 **Scope 批量 join**，**阻塞当前线程**直到子线程全部结束（[§三 §3](#3-分层拆解自动-join-做了什么是不是封装系统调用)）。

4. **`.join()` 底层**
   两种句柄都有 **`.join()`**；手动 / 自动 join 最终走**同一套** OS 等待 API（`pthread_join` / `WaitForSingleObject`），差别只在 std **包装层**与**生命周期**。

## 四、参数 `s` 是什么？从哪来？

闭包里的 **`s`** 不是关键字，也不是全局变量——只是你给参数起的名字；本质是标准库传入的 **`&Scope<'env>`** 引用。

### 1. `thread::scope` 签名（简化）

```rust
pub fn scope<'env, F, T>(f: F) -> T
where
    F: for<'scope> FnOnce(&'scope Scope<'scope, 'env>) -> T,
```

| 部分 | 含义 |
|------|------|
| **`thread::scope`** | 标准库函数；你传入一个闭包 `f` |
| **`for<'scope> …`** | 高阶生命周期：闭包接收的 `Scope` 引用带 **`'scope`** |
| **`&'scope Scope<…>`** | 就是闭包参数 **`s`** 的类型（写成 `\|s\|` 只是习惯命名） |
| **返回值 `T`** | scope 闭包最后一行的表达式，可带回 scope 外 |

### 2. 执行流程（通俗版）

```rust
thread::scope(|s| {
    // s = &Scope，由 std 在调用闭包前创建并传入
    s.spawn(|| { /* … */ });
});
```

1. 调用 `thread::scope(你的闭包)`；
2. std **内部新建** `Scope` 结构体，维护尚未 join 的 `ScopedJoinHandle` 列表；
3. std 把 **`&Scope`** 传给你的闭包，绑定到变量 `s`（名字可改）；
4. 每次 **`s.spawn(...)`** 创建 OS 线程，登记 handle，返回 **`ScopedJoinHandle<'scope, T>`**；
5. 闭包执行完毕 → **`Scope` 析构** → 对未 join 的 handle **批量 `.join()`**（见 [§三 §3](#3-分层拆解自动-join-做了什么是不是封装系统调用)）；
6. `thread::scope` 返回闭包的结果 `T`。

### 3. `Scope` 与 `s.spawn`（伪代码）

```rust
struct Scope<'scope, 'env: 'scope> {
    // 登记 spawn 出的 handle，供收尾 batch join
    handles: /* 内部容器 */,
}

impl<'scope, 'env: 'scope> Scope<'scope, 'env> {
    pub fn spawn<F, T>(&self, f: F) -> ScopedJoinHandle<'scope, T>
    where
        F: FnOnce() -> T + Send + 'scope,
        T: Send + 'scope,
    {
        // 创建 OS 线程，包装成 ScopedJoinHandle，登记到 handles
    }
}
```

- **`s` 的类型**：`&Scope<'scope, 'env>`（闭包里常写成 `&Scope<'_>`）；
- **改名合法**：`thread::scope(|scope_obj| { scope_obj.spawn(|| {}); })` 与 `|s|` 完全等价；
- **外部拿不到 `Scope`**：实例只在 `thread::scope` 内部临时存在，生命周期 = 闭包执行期间，无法 return 到 scope 外。

### 4. 极简对照

| | `thread::spawn()` | `s.spawn()` |
|---|-------------------|-------------|
| 返回 | `JoinHandle<T>` | `ScopedJoinHandle<'scope, T>` |
| 捕获 | 强制 `move` / `'static` | 可借 scope 外栈变量 |
| 等待 | 手动 join | scope 收尾自动 join + 可选手动 join |
| **`s` 从哪来** | — | `thread::scope` 内部构造 `Scope` 并把 **`&Scope`** 传入闭包 |

## 五、scope 内外的变量规则

| 变量位置 | 在 `s.spawn` 里怎么用 | scope 外还能用吗 |
|----------|----------------------|------------------|
| scope **上面**（闭包外、调用前定义） | 直接借用，**不必 move** | ✅ scope 结束后仍可用（若没被 move 进某线程） |
| scope **内部**（闭包 `{ }` 里定义） | 通常 **`move`** 进子线程 | ❌ 不能把 `inside_scope` 当普通变量拿到外面 |
| scope **返回值** | 闭包最后一行表达式 | ✅ `let x = thread::scope(\|s\| { … })` |

```rust
use std::thread;

fn main() {
    let before = 10;

    let result = thread::scope(|s| {
        let inside = 20;

        s.spawn(|| println!("借 before: {before}"));

        s.spawn(move || println!("move inside: {inside}"));

        before + inside // scope 闭包返回值
    });

    println!("{result:?}");
    // println!("{inside}"); // 编译错误：inside 作用域仅在 scope 闭包内
}
```

## 六、如何把 scope 内的结果带到外面

子线程若在 scope **内部**创建，其栈上局部变量**不能**直接在外面访问。常用三种出路：

### 1. scope 闭包返回值（最简单）

```rust
let sum = thread::scope(|s| {
    let nums = vec![1, 2, 3, 4, 5];
    let total: i32 = nums.iter().sum();
    s.spawn(move || println!("子线程: sum = {total}"));
    total // 返回给 scope 外
});
```

### 2. 在 scope 外创建 `Arc<Mutex<T>>`（多线程汇总）

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let acc = Arc::new(Mutex::new(0));

thread::scope(|s| {
    for i in 1..=5 {
        let acc = Arc::clone(&acc);
        s.spawn(move || {
            *acc.lock().unwrap() += i;
        });
    }
});

println!("{}", *acc.lock().unwrap());
```

> `Arc` 本身 `'static` 友好；scope 只解决「**借用栈上数据**」的问题，**长期跨线程共享可变状态**仍靠 [1.3](./1.3-shared-ownership.md) / [1.7 Mutex](./1.7-mutex-rwlock.md)。

### 3. 数据本来就在 scope 外，子线程只负责写

把要修改的结构定义在 `thread::scope` **之前**，子线程里通过 `Mutex` / 原子类型更新；scope 结束后读最终值（同 Demo 示例 4）。

## 七、对照表：`thread::spawn` vs `thread::scope`

> 两个 spawn 带类型标注见 [§二 §0](#0-两个-spawn-完整区分带类型标注)；`s` 来源见 [§四](#四参数-s-是什么从哪来)。

| | **`thread::spawn`** | **`thread::scope`** |
|---|---------------------|---------------------|
| 线程寿命 | 与进程同级，可超过创建者栈帧 | **限于 scope 块**，结束必 join |
| 借用局部变量 | ❌ 须 `'static` / `move` | ✅ 可借 `'scope` 内数据 |
| 等待方式 | 手动 `.join()` 每个 handle | scope 结束**自动** join 全部 |
| handle 逃逸 | 可以（也易漏 join） | **不可**把 `ScopedJoinHandle` 带出 scope |
| 典型场景 | 后台任务、与 caller 生命周期解耦 | 短生命周期并行、map-reduce 式批处理 |
| 稳定版本 | 1.0 起 | **1.63** 起 |

```rust
use std::thread;

let vec = vec![1, 2, 3];

// spawn：必须 move，vec 所有权进子线程
let h = thread::spawn(move || println!("{:?}", vec));
h.join().unwrap();
// vec 此处已不可用

let vec2 = vec![4, 5, 6];
thread::scope(|s| {
    s.spawn(|| println!("{:?}", vec2)); // 借用即可
});
// vec2 仍可用
```

## 八、历史：Leakpocalypse 与 Rust 1.63

Rust **1.0 之前**曾提供基于 **`JoinGuard` + `Drop` 自动 join** 的 `scoped` 线程 API：guard 离开作用域时在 `Drop` 里 join 子线程，看起来能安全借用栈上数据。

**Leakpocalypse**（社区对这次设计失败的称呼）：

1. `mem::forget(guard)`、**循环引用**等可以让 guard **永不 Drop**；
2. 子线程继续跑，却**不再被 join**，仍借用已失效的栈内存 → **Unsound**（安全 API 在 leak 下失效）；
3. 该 API 在 **1.0 前被移除**。

**准则**：**安全 API 不能假设「对象一定会被 Drop」**。

直到 **Rust 1.63**，标准库用 **`thread::scope` 闭包** 重新实现：

- 子线程 handle **不能逃出** scope（类型系统保证）——`mem::forget(handle)` 也无法让子线程在 scope 外继续借栈（与 Leakpocalypse 根本差别）；
- **借用安全**由 **`'scope`** 生命周期编码，**不**假设「用户一定会 drop 某个 guard」；
- **自动 join** 仍由 std 在 scope 收尾时批量调用 `.join()`（常见实现走 `Scope` 析构；见 [§三 §3 分层拆解](#3-分层拆解自动-join-做了什么是不是封装系统调用)），底层与手动 join **同一条 OS 路径**。

## 九、新手易错

1. **把 Enjoy 当 Join**：正确是 **`JoinHandle` / `.join()`**（见 [1.1.2 §五](./1.1.2-join-handle.md#五两个易混点)）。
2. **以为 scope = 可以随意并发写同一变量**：没有 `Mutex` / 原子类型时，多个 `&mut` 仍会被编译器拒绝。
3. **在 scope 里 `sleep` 很久却以为「不阻塞主线程」**：`thread::scope` **会阻塞调用它的线程**（通常就是主线程），只是帮你自动 join。
4. **纠结子线程打印顺序**：同一 scope 里多个 `s.spawn` 的执行顺序**不确定**，调试请加线程名或序号。
5. **scope 能借局部变量，就不用 `Arc` 了？** 仅当**所有线程一定在 scope 内结束**且只需**借用**时成立；线程要活得比函数更久 → 仍用 `spawn` + `Arc`（见 [1.3](./1.3-shared-ownership.md)）。
6. **把「自动 join」当成 spawn 也有**：只有 **`thread::scope`** 在闭包结束时批量 join；**`thread::spawn` 必须手动**（见 [§三](#三join-方法与-scope-自动-join别混成一件事)）。
7. **以为 auto join 是内核自动回收**：OS 不会等子线程；自动 = std 替你调 `.join()` → 仍走 `pthread_join` / `WaitForSingleObject`（见 [§三 §3](#3-分层拆解自动-join-做了什么是不是封装系统调用)）。
8. **把 `s` 当成关键字或全局变量**：`s` 只是 `&Scope` 的参数名，由 `thread::scope` 创建并传入（见 [§四](#四参数-s-是什么从哪来)）。
9. **scope 自动 join 能拿到子线程返回值**：自动 join **丢弃 `Ok(T)`**；要 **`T`** 须在 scope 内手动 `.join()`（见 [§三 §5](#5scope-自动-join-时resultt-_-怎么处理)）。
10. **把 spawn 写成 swap**：创建线程是 **`spawn`**；泛型约束逐条见 [1.1.3](./1.1.3-send-static-spawn.md) 与 [§约束对照](#两段-spawn-泛型约束对照)。
11. **以为带生命周期就一定是引用**：`'static` / `'scope` 只约束**借用**须活够久；**`move` 转移所有权**无 `&`，同样合法（见 [`'static` vs `'scope` 深拆](#static-vs-scope生命周期深拆) §3）。
