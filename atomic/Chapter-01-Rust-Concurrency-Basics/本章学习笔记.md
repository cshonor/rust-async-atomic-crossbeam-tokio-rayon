## 1. 并发基础概念与线程基础模型

并发编程的核心：让多个计算过程**安全、高效地重叠执行**。

### 进程与线程

| 概念 | 隔离 | 内存 | 交互 |
|------|------|------|------|
| **进程** | 相互隔离 | 默认不共享 | OS 快速切换，看起来「同时」 |
| **线程** | 同进程内无隔离 | **共享** | 通过共享内存交互 |

### 线程标识（`ThreadId`）

- 标准库为每线程分配唯一 **`ThreadId`**。  
- 用途：复制、比较相等；**无其他特殊语义**，**不保证连续编号**。

## 2. 基础并发问题由来与借用规则

多线程共享内存易出错；Rust 在**编译期**用类型系统挡住绝大多数问题。

### 数据竞争（Data Race）

> 一线程**修改**数据，另一线程**同时访问**（读或写）同一块数据 → **数据竞争**。

在 Rust / C/C++ 中 → **未定义行为（UB）**。

### 未定义行为（UB）

违反语言底层规则时，优化器可能基于错误假设 → 崩溃、读错内存、逻辑不可预测（书中「时光倒流」式混乱）。

### 借用规则如何防数据竞争

| 借用 | 准确称呼 | 规则 |
|------|----------|------|
| `&T` | **共享借用**（Shared Reference） | 可复制、多方共享；默认不可改 |
| `&mut T` | **排他借用**（Exclusive Reference） | 同一时刻仅一个活跃借用；改时无人共读 |

**一句话**：共享读 OR 独占写，编译期排除「同时读写」。

## 3. 线程创建与基础通信方式

### 3.1 线程创建

| API | 要点 |
|-----|------|
| **`std::thread::spawn`** | 新线程跑闭包；闭包数据须 **`'static`** → 通常 **`move`** 转移所有权，不能捕获非静态局部引用 |
| **`thread::Builder`** | `spawn` ≈ `Builder::new().spawn().unwrap()`；可设**栈大小**、**线程名**、返回 **`Result`**（失败不直接 panic） |
| **`std::thread::scope`** | 保证子线程在作用域结束前结束 → 可**安全借用局部变量**；`s.spawn` + 作用域结束自动 **join**，绕过 `'static` |

### 3.2 共享数据的所有权（两线程寿命都不确定时）

须让数据活得和**最长寿程**一样久：

| 方式 | 说明 | 注意 |
|------|------|------|
| **`static`** | 全程序拥有，永远存在 | 任何线程可借 |
| **`Box::leak`** | 放弃所有权，得 `'static` 引用 | 频繁泄漏会耗尽内存 |
| **`Rc` / `Arc`** | 引用计数共享所有权，计数为 0 释放 | **`Rc` 非线程安全**；跨线程用 **`Arc`**（计数修改 **atomic**） |

## 4. 内部可变性与并发安全标记

共享 `&T` 默认不能改 → 需要 **内部可变性（Interior Mutability）**。

### 内部可变性一览

| 场景 | 类型 | 行为 |
|------|------|------|
| 单线程 | `Cell<T>` | 整体替换 |
| 单线程 | `RefCell<T>` | 运行时记借用次数，冲突 **panic** |
| 多线程 | **Atomics** | 类似 `Cell`，无锁跨线程改（第 2 章展开） |
| 多线程 | **`Mutex<T>` / `RwLock<T>`** | 类似 `RefCell`，冲突时**阻塞** |

底层构建块：**`UnsafeCell<T>`** — 无安全检查，由上层类型保证不 UB。

### `Send` 与 `Sync`（Auto traits）

| Trait | 含义 |
|-------|------|
| **`Send`** | 所有权可安全移到另一线程 |
| **`Sync`** | 可安全跨线程共享（`&T` 是 `Send`） |

结构体字段都满足则自动满足；可用 **`PhantomData`** 显式**不**实现。

## 5. 锁与等待机制

### `Mutex<T>`

- **数据在锁里**（与 C++「锁与数据分离」不同）：必须先 `lock()` 得 **`MutexGuard`**（类似 `&mut T`），**Drop 时自动解锁**。  
- **锁中毒（Lock Poisoning）**：持锁线程 **panic** → `Mutex` 标记中毒，强制处理可能不一致的数据。

### `RwLock<T>`

- 多读 **或** 一写；读多写少场景。

### Thread Parking

- `thread::park()` 休眠；`Thread::unpark()` 唤醒。  
- **`unpark` 先于 `park`**：请求被记录，下次 `park` **直接返回** → 避免唤醒丢失。

### `Condvar`

- `Condvar::wait(guard)`：**原子地**解锁 `Mutex` 并休眠；被 `notify_one` / `notify_all` 唤醒后**重新加锁**。  
- 比 park 更适合「等条件」；仍须防**虚假唤醒**（见 §8）。

## 6. 本章核心术语

| 术语 | 含义 |
|------|------|
| **Shared / Exclusive Reference** | `&T` / `&mut T` 的准确叫法 |
| **Data Race** | 并发读写同内存 → UB |
| **Interior Mutability** | 通过 `&T` 改内部数据 |
| **Send / Sync** | 跨线程移所有权 / 跨线程共享引用 |
| **Lock Poisoning** | 持锁 panic 后锁状态保护 |
| **Spurious Wake-up** | park / condvar 无明确信号也可能醒 → **必须 `loop` 查条件** |
| **Writer Starvation** | `RwLock` 读者不断占锁，写者永远拿不到 |

## 8. 新手必备认知与易错点

### 必备认知

1. **不要靠「一定会 Drop」设计安全**：循环引用、`mem::forget` 等可不调用 Drop → 早期 `thread::scoped` 类 API 不安全（**Leakpocalypse**）。  
2. **先解决所有权与生命周期**：报错时想 **`scope`** 还是 **`Arc`**。  
3. **`Mutex` 保护的是数据**：要改必先拿锁；类型系统禁止「裸引用绕过锁」。

### 高频易错点

| # | 坑 | 正确做法 |
|---|-----|----------|
| 1 | **锁持有过久** | `MutexGuard` 绑作用域；I/O / `sleep` 前用 `{}` 或 `drop(guard)` |
| 2 | **`if let` 延长锁** | `if let Some(x) = list.lock().unwrap().pop()` 会让 guard 活到整个 `if` 结束 → 先 `let item = list.lock()…pop()` 再 `if let` |
| 3 | **忽略虚假唤醒** | `park` / `condvar::wait` 必须放在 **`loop`/`while` 里反复检查条件**，不能单独 `if` |
| 4 | **`Rc`/`RefCell` 跨线程** | 报 `Send` not implemented → 换 **`Arc` + `Mutex`/`RwLock`** |

## 面试 / 笔试一句话（第一章）

**Rust 并发从线程共享内存出发，用共享/排他借用防数据竞争；跨线程用 `'static`/`Arc`/`scope` 解决所有权；用内部可变性 + `Mutex`/`Condvar`/原子类型安全共享可变状态；`Send`/`Sync` 标记线程安全边界。**
