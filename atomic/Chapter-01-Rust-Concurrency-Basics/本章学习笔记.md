## 1. 并发基础概念与线程基础模型

并发编程的核心：让多个计算过程**安全、高效地重叠执行**。

### 进程与线程

| 概念 | 隔离 | 内存 | 交互 |
|------|------|------|------|
| **进程** | 相互隔离 | 默认不共享 | OS 快速切换，看起来「同时」 |
| **线程** | 同进程内无隔离 | **共享** | 通过共享内存交互 |

### 主线程与程序生命周期

- 每个程序从**主线程**执行 `main` 开始。  
- **`main` 返回 → 整个程序立即退出**，即使其他 `spawn` 出的线程仍在运行（未 `join` 的子线程会被终止）。  
- 要拿到返回值或确保子线程跑完，必须对 `JoinHandle` 调用 **`join()`**；子线程 **panic** 时 `join()` 返回带 panic 信息的 **`Result::Err`**。

### 线程标识（`ThreadId`）

- 标准库为每线程分配唯一 **`ThreadId`**。  
- 用途：复制、比较相等；**无其他特殊语义**，**不保证连续编号**。

## 2. 基础并发问题由来与借用规则

多线程共享内存易出错；Rust 在**编译期**用类型系统挡住绝大多数问题。

### 数据竞争（Data Race）

> 一线程**修改**数据，另一线程**同时访问**（读或写）同一块数据 → **数据竞争**。

在 Rust / C/C++ 中 → **未定义行为（UB）**。

### 未定义行为（UB）与 Unsound

违反语言底层规则时，优化器可能基于「别名规则永不被打破」的假设做**指令重排、消除无效分支**等优化 → 崩溃、读错内存、逻辑不可预测（书中「**时光倒流**」：UB 甚至可让 UB **之前**的正确代码也被优化器破坏）。

在 `unsafe` 中违背借用规则引发数据竞争 → **Unsound（破防）** → UB。

### 借用规则如何防数据竞争

| 借用 | 准确称呼 | 规则 |
|------|----------|------|
| `&T` | **共享借用**（Shared Reference） | 可复制、多方共享；默认不可改 |
| `&mut T` | **排他借用**（Exclusive Reference） | 同一时刻仅一个活跃借用；改时无人共读 |

**一句话**：共享读 OR 独占写，编译期排除「同时读写」。

## 3. 线程创建与基础通信方式

### 3.1 线程创建

| API | 要点 |
|-----|------|
| **`std::thread::spawn`** | 新线程跑闭包；闭包须 **`'static`** → 通常 **`move`** 转移所有权，**不能捕获非静态局部引用** |
| **`JoinHandle::join()`** | 阻塞等待线程结束；panic 时返回 `Err` |
| **`thread::Builder`** | `spawn` ≈ `Builder::new().spawn().unwrap()`；可设**栈大小**、**线程名**（调试）、返回 **`io::Result`**（资源不足时不直接 panic） |
| **`std::thread::scope`** | 子线程保证在作用域结束前结束 → 可**安全借用局部变量**；`s.spawn` + 作用域结束**自动 join**，绕过 `'static` |

**易错细节**：`println!` 底层对 **`Stdout::lock()`**，避免多线程输出在**字节级**被截断或交错（仍可能行级交错）。

### 3.2 Scoped Threads 与 Leakpocalypse

- **`scope` 内**：多线程可**并发共享读**同一局部变量；若某线程要**可变借用**，编译器禁止其他线程同时访问 → 编译期防数据竞争。  
- **历史**：1.0 前曾有基于 **`JoinGuard` + `Drop` 自动 join** 的 `scoped` API。  
- **Leakpocalypse**：`mem::forget`、循环引用等可**泄漏** guard 而不触发 `Drop` → 依赖 Drop 的安全接口 **Unsound**。  
- **准则**：**安全 API 不能假设「对象一定会被 Drop」**。直到 **Rust 1.63** 才用闭包作用域设计重新提供安全的 **`thread::scope`**。

### 3.3 共享数据的所有权（两线程寿命都不确定时）

须让数据活得和**最长寿程**一样久；`Rc`/`Arc` 本质是**共享引用**，默认**不可改**内部数据：

| 方式 | 说明 | 注意 |
|------|------|------|
| **`static`** | 全程序拥有，永远存在 | 任何线程可借 |
| **`Box::leak`** | 放弃所有权，得 `'static` 引用 | 实质泄漏；频繁调用会耗尽内存 |
| **`Rc` / `Arc`** | 引用计数；计数为 0 释放 | **`Rc` 非线程安全**（改计数非 atomic）；跨线程用 **`Arc`** |
| **克隆 + 遮蔽** | `let a = a.clone();` 再 `move \|\| …` | 利用**变量遮蔽**避免 `a1,a2,…` 重命名地狱 |

## 4. 内部可变性与并发安全标记

共享 `&T` 默认不能改 → 需要 **内部可变性（Interior Mutability）**——在共享引用下合法修改数据的「逃生舱」。

### 内部可变性一览

| 场景 | 类型 | 行为 |
|------|------|------|
| 底层 | **`UnsafeCell<T>`** | 无安全检查，暴露 `*mut T`；由外层或 `unsafe` 保证不 UB |
| 单线程 | `Cell<T>` | 整体替换；不能借内部数据 |
| 单线程 | `RefCell<T>` | 运行时记借用次数，冲突 **panic**（避免 UB） |
| 多线程 | **Atomics** | `Cell` 的并发版；硬件保证读写的不可分割性（通常小整数/指针，第 2 章展开） |
| 多线程 | **`Mutex<T>` / `RwLock<T>`** | `RefCell` 的并发版；冲突时**阻塞（Sleep）**而非 panic |

### `Send` 与 `Sync`（Auto traits / Marker traits）

| Trait | 含义 |
|-------|------|
| **`Send`** | 所有权可安全移到另一线程 |
| **`Sync`** | 可安全跨线程共享 ⇔ **`&T` 是 `Send`** |

**常见类型**：

| 类型 | Send | Sync | 记忆 |
|------|------|------|------|
| `i32`、`bool` 等 | ✓ | ✓ | 基础类型 |
| `Rc<T>` | ✗ | ✗ | 计数非 atomic |
| `Cell<T>`（T: Send） | ✓ | ✗ | 可 move，共享则竞态 |
| `RefCell<T>` | ✓ | ✗ | 同 Cell 逻辑 |
| `Arc<T>` | T 决定 | T 决定 | T: Send + Sync 时通常两者皆可 |
| `*const T` / `*mut T` | ✗ | ✗ | 裸指针 |

- **自动衍生**：字段都满足则结构体自动满足。  
- **手动阻断**：`PhantomData<Cell<T>>` 等，编译期零开销取消 `Send`/`Sync`。  
- **手动承诺**：`unsafe impl Send/Sync`（确认裸指针封装安全时使用）。

## 5. 锁与等待机制

> **全书 Mutex 体系**（含 OS 原语、三态优化、与第 6 章 Arc 区分）：[互斥锁与锁体系-贯通笔记.md](../互斥锁与锁体系-贯通笔记.md)

### `Mutex<T>`

- 与 C++「锁与数据分离」不同：Rust **`Mutex<T>` 包裹数据**，类型系统保证**不加锁拿不到数据**。  
- `.lock().unwrap()` → **`MutexGuard`**：通过 **`DerefMut`** 当作 `&mut T`；**Drop 时自动解锁**（RAII）。  
- **锁作用域陷阱**：`if let Some(x) = list.lock().unwrap().pop()` 会让 guard 活到**整个 `if` 块** → 先 `let item = list.lock().unwrap().pop();` 再分支。  
- **锁中毒（Lock Poisoning）**：持锁线程 **panic** → `Mutex` 标记中毒；后续 `lock()` 得 `Err`，防读不一致脏数据；`.unwrap()` 即接受传染。

### `RwLock<T>`

- 多读（**`ReadGuard`**，共享读）**或** 一写（**`WriteGuard`**，排他写）；读多写少。  
- **写者饥饿（Writer Starvation）**：读者连绵不断时，写者可能长期拿不到锁。  
- **全书深度**（写优先状态机、与 Mutex 选型）：[RwLock与读写锁体系-贯通笔记.md](../RwLock与读写锁体系-贯通笔记.md)

### Thread Parking

- `thread::park()` 休眠；`Thread::unpark()` 唤醒。  
- **`unpark` 先于 `park`**：信号**不丢失**，下次 `park` **直接返回**。  
- **局限**：适合简单一对一通知；多生产者/多消费者下精准唤醒特定线程很复杂。

### `Condvar`

- 必须与 **`Mutex`** 绑定；`condvar.wait(guard)` **原子地**解锁并休眠，唤醒后**重新加锁** — 解决「放锁与休眠之间丢通知」的竞态。  
- `notify_one()` / `notify_all()`。  
- **生产者-消费者、惊群、持锁 notify**：见 [Condvar与条件变量-贯通笔记.md](../Condvar与条件变量-贯通笔记.md)；代码 **`1.9-parking-condvar/1.9-parking-condvar-demo.rs`**  
- **虚假唤醒**：`park` / `wait` 可能无信号自行苏醒 → 条件检查必须在 **`while`/`loop`** 内，**不能**单独 `if`。

## 6. 本章核心术语

| 术语 | 含义 |
|------|------|
| **Shared / Exclusive Reference** | `&T` / `&mut T` 的准确叫法 |
| **Data Race** | 并发读写同内存 → UB |
| **Interior Mutability** | 通过 `&T` 改内部数据 |
| **Send / Sync** | 跨线程移所有权 / 跨线程共享引用 |
| **Lock Poisoning** | 持锁 panic 后锁状态保护 |
| **Spurious Wake-up** | park / condvar 无明确信号也可能醒 → **必须 `loop` 查条件** |
| **Leakpocalypse** | 依赖 Drop 的 scoped 线程 API 因 leak 而 Unsound |
| **Writer Starvation** | `RwLock` 读者不断占锁，写者永远拿不到 |

## 8. 新手必备认知与易错点

### 必备认知

1. **不要靠「一定会 Drop」设计安全**：循环引用、`mem::forget` 等可不调用 Drop → 早期 `thread::scoped` 类 API 不安全（**Leakpocalypse**）。  
2. **先解决所有权与生命周期**：报错时想 **`scope`** 还是 **`Arc`**。  
3. **`Mutex` 保护的是数据**：要改必先拿锁；类型系统禁止「裸引用绕过锁」。

### 高频易错点

| # | 坑 | 正确做法 |
|---|-----|----------|
| 1 | **锁持有过久** | `MutexGuard` 绑作用域；I/O / `sleep` 前用 `{}` 或 `drop(guard)` |
| 2 | **`if let` 延长锁** | `if let Some(x) = list.lock().unwrap().pop()` 会让 guard 活到整个 `if` 结束 → 先 `let item = list.lock()…pop()` 再 `if let` |
| 3 | **忽略虚假唤醒** | `park` / `condvar::wait` 必须放在 **`loop`/`while` 里反复检查条件**，不能单独 `if` |
| 4 | **`Rc`/`RefCell` 跨线程** | 报 `Send` not implemented → 换 **`Arc` + `Mutex`/`RwLock`** |

## Summary（本章小结）

- 程序由多线程组成；**主线程 `main` 返回即退出整个进程**（未 join 的子线程被终止）。  
- **共享/排他借用**在编译期杜绝安全代码中的数据竞争，避免 UB。  
- 跨线程共享：`Send`/`Sync` + `'static` / **`scope`** / **`Arc`** / `static` / `leak`。  
- **`UnsafeCell`** 开启内部可变性 → `Cell`/`RefCell` → 多线程 **`Atomics`**、`Mutex`、`RwLock`。  
- 等条件用 **park/unpark** 或 **`Condvar`+`Mutex`**，避免忙等；**必 `loop` 查条件**防虚假唤醒。

## 面试 / 笔试一句话（第一章）

**Rust 并发从线程共享内存出发，用共享/排他借用防数据竞争；跨线程用 `'static`/`Arc`/`scope` 解决所有权；用内部可变性 + `Mutex`/`Condvar`/原子类型安全共享可变状态；`Send`/`Sync` 标记线程安全边界。**
