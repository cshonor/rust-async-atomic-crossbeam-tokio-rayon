## 1.4 Borrowing and Data Races（借用与数据竞争）

> 书 §1.4 · 承接 [1.2 scope 借用规则](./1.2-scoped-threads.md) · 共享可变见 [1.5](./1.5-interior-mutability.md)、[1.7 Mutex](./1.7-mutex-rwlock.md)

---

## 一、多线程共享内存为什么危险

同一进程内线程**共用地址空间**，读写同一块内存若缺乏协调，就会出现**数据竞争（Data Race）** → 在 Rust / C/C++ 中属于**未定义行为（UB）**：崩溃、读错值、逻辑不可预测，且**难以复现**。

Rust 的策略：在**编译期**用借用规则挡住绝大多数「同时读写」；实在要绕过，必须进 **`unsafe`** 并自行保证不 UB。

---

## 二、数据竞争（Data Race）定义

> **一线程正在修改**某内存，**另一线程同时访问**（读或写）**同一块**内存，且至少一侧无同步 → **数据竞争**。

```rust
// 伪代码：两个线程无同步地写/读同一 i32 —— UB
// 线程 A: *ptr = 1;
// 线程 B: let x = *ptr;
```

在**安全 Rust** 里，普通 `&T` / `&mut T` 无法跨线程构成这种模式；问题常出现在 `unsafe`、错误使用 `static mut`、或与 C 互操作。

---

## 三、未定义行为（UB）与 Unsound

### 1. UB 是什么

违反语言**内存模型 / 别名规则**时，编译器可假设「规则永不被打破」，从而：

- **指令重排**、删除「看似无效」的分支；
- 让 UB **之前**看起来正确的代码也产生荒谬结果（书中「**时光倒流**」式例子）。

### 2. Unsound（破防）

在 **`unsafe`** 里违背借用规则、人为制造数据竞争 → API 声称安全但实际可 UB → 称为 **Unsound**。  
（对比：[1.2 Leakpocalypse](./1.2-scoped-threads.md) 是「安全 API 在 leak 下 Unsound」。）

---

## 四、借用规则如何防数据竞争

Rust 对**单次线程内**的引用有两条铁律，推广到 [1.2 scope](./1.2-scoped-threads.md) 的多线程借用检查：

| 借用 | 准确称呼 | 规则 |
|------|----------|------|
| `&T` | **共享借用**（Shared Reference） | 可同时存在多个；**默认不可改** |
| `&mut T` | **排他借用**（Exclusive Reference） | 同一时刻**至多一个**活跃；写时无人共读 |

**一句话**：**共享读 OR 独占写**——编译期排除「一边写、一边读/写」。

```rust
use std::thread;

fn main() {
    let mut v = vec![1, 2, 3];
    thread::scope(|s| {
        s.spawn(|| println!("{:?}", v)); // 共享读 OK
        // s.spawn(|| v.push(4));        // 编译错误：不能同时 &mut
    });
}
```

## 五、从借用到并发同步（路线图）

| 需求 | 工具 |
|------|------|
| 多线程**只读**同一份 `'static` / `Arc` 数据 | 通常安全（`T: Sync`） |
| 多线程**写**同一份数据 | `Mutex` / `RwLock` / 原子类型 |
| 单线程内「`&self` 但要改字段」 | `Cell` / `RefCell`（[1.5](./1.5-interior-mutability.md)） |
| 等条件成立再往下走 | `Condvar`（[1.8](./1.8-parking-condvar.md)） |

## 六、对照：编译期 vs 运行时检查

| | **借用检查（& / &mut）** | **`RefCell`（单线程）** | **`Mutex`（多线程）** |
|---|-------------------------|-------------------------|------------------------|
| 时机 | 编译期 | 运行时 panic | 阻塞等待 |
| 冲突时 | 编译错误 | panic | 睡眠，不 panic |
| 跨线程 | scope / Sync 规则 | ❌ 不能 Sync | ✅ 设计目标 |

---

## 七、新手易错

1. **「多线程读同一 `&mut`」**：不可能通过编译；要么拆成共享读，要么加锁。
2. **在 `unsafe` 里手动拆引用**：自己承担不 UB 的证明；否则 Unsound。
3. **把数据竞争当成「偶尔算错」**：UB 下优化器行为不可预测，不是「概率 bug」。
4. **scope 里随便改**：scope 只解决**生命周期**，**不**自动允许并发 `&mut`；仍须 Mutex 或单写者模式。
