## 1.6 Send 与 Sync

> 书 §1.6 · 承接 [1.3 Arc](./1.3-shared-ownership.md)、[1.5 内部可变性](./1.5-interior-mutability.md) · 组合用法见 [1.7 `Arc<Mutex<T>>`](./1.7-mutex-rwlock.md)

---

## 一、为什么需要 Send / Sync

`thread::spawn` 闭包要求 **`Send + 'static`**。编译器要回答两个问题：

1. **所有权**能否安全**移到**另一线程？→ **`Send`**
2. **共享引用 `&T`** 能否安全**跨线程**使用？→ **`Sync`**

二者是 **auto trait（自动 trait）/ marker trait**：无方法，只表达「线程安全边界」；结构体字段都满足则自动满足。

---

## 二、定义（一句话）

| Trait | 含义 |
|-------|------|
| **`Send`** | 类型 `T` 的**所有权**可安全转移到另一线程 |
| **`Sync`** | 类型 `T` 可安全被多线程**共享引用** ⇔ **`&T: Send`** |

**记忆**：

- **`Send`**：把**值本身** `move` 进 `spawn`。
- **`Sync`**：多个线程同时持 **`&T`**（例如 `Arc` 里的共享）。

---

## 三、常见类型速查

| 类型 | Send | Sync | 记忆 |
|------|------|------|------|
| `i32`、`bool`、`String` | ✓ | ✓ | 基础类型 / 拥有堆数据 |
| `Rc<T>` | ✗ | ✗ | 引用计数非 atomic |
| `Cell<T>`（`T: Send`） | ✓ | ✗ | 可 move；共享则竞态 |
| `RefCell<T>` | ✓* | ✗ | 运行时借用非线程安全 |
| `Arc<T>` | 看 `T` | 看 `T` | `T: Send + Sync` 时通常两者皆可 |
| `Mutex<T>` | 看 `T` | 看 `T` | 锁保护下的 `T` |
| `*const T` / `*mut T` | ✗ | ✗ | 裸指针无自动保证 |

\* `RefCell` 本身可 move 到子线程，但**不能**在多线程间共享 `&RefCell`。

## 四、`Send` 精读：所有权跨线程

```rust
use std::thread;

let text = String::from("hello");
let h = thread::spawn(move || {
    println!("{text}"); // 子线程拥有 text
});
h.join().unwrap();
// println!("{text}"); // 编译错误：已 move
```

**未实现 `Send` 的反例**：`Rc<i32>` 不能 `move` 进 `spawn`（计数器非原子，跨线程 move 会破坏 `Rc` 不变量）。

仓库对应：Demo `demo_send_trait`、`demo_not_send`

## 五、`Sync` 精读：引用跨线程共享

```rust
use std::sync::Arc;
use std::thread;

let shared = Arc::new(100);
let a = Arc::clone(&shared);
let h1 = thread::spawn(move || println!("{a}"));
let b = Arc::clone(&shared);
let h2 = thread::spawn(move || println!("{b}"));
h1.join().unwrap();
h2.join().unwrap();
println!("主线程: {shared}"); // 仍可读
```

**未实现 `Sync` 的反例**：不能把 `&RefCell<i32>` 分给两个线程同时 `borrow()`。

仓库对应：Demo `demo_sync_trait`、`demo_not_sync`

## 六、`Arc<Mutex<T>>` 组合（Send + Sync 落地）

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let data = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..5 {
    let d = Arc::clone(&data);
    handles.push(thread::spawn(move || {
        *d.lock().unwrap() += 1;
    }));
}
for h in handles {
    h.join().unwrap();
}
println!("{}", *data.lock().unwrap());
```

| 组件 | 贡献 |
|------|------|
| **`Arc`** | 多线程共享**同一把锁**的句柄（`Sync`） |
| **`Mutex`** | 同一时刻只有一个线程改内部 `T` |
| **`move` + `Send`** | 每个线程拿走自己的 `Arc` 克隆 |

仓库对应：Demo `demo_send_and_sync_combined`、`demo_practical_example`

## 七、手动控制 Send / Sync

| 手段 | 用途 |
|------|------|
| **自动衍生** | 字段都 `Send`/`Sync` 则 struct 自动满足 |
| **`PhantomData<Cell<T>>`** 等 | 编译期**取消** auto Send/Sync（零运行时开销） |
| **`unsafe impl Send/Sync`** | 封装裸指针等：作者证明跨线程安全 |

> 只有确认封装正确时才 `unsafe impl`；否则 Unsound。

---

## 八、对照：`Send` vs `Sync`

| | **`Send`** | **`Sync`** |
|---|------------|------------|
| 问的是 | 值 **move** 到子线程？ | **`&T`** 跨线程共享？ |
| 典型 API | `thread::spawn(move \|\| …)` | `Arc::clone` 多线程读 |
| 关系 | `T: Sync` ⇒ `&T: Send` | 反之不成立 |
| 报错方向 | 「cannot be sent between threads」 | 「cannot be shared between threads safely」 |

---

## 九、新手易错

1. **混淆 Send 与 Sync**：`spawn` 要 **Send**；`Arc` 共享要内部 **`T: Send + Sync`**。
2. **以为 `Arc` 就能改**：只读共享；写要 `Mutex` / 原子。
3. **在多个线程里用 `Rc` / `RefCell`**：应换 `Arc` / `Mutex`。
4. **裸指针自己 `Send`**：指针可 move，但解引用安全要你证明。
