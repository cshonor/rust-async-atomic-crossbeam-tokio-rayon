## 2. 核心设计（四个问题）

### 2.1 避免多余分配：`MaybeUninit<T>`

- 通道槽位用 **`UnsafeCell<MaybeUninit<T>>`**，不必为「尚未写入」多包一层 `Option<T>` 的判别式开销（教学向；生产用标准库更安全）。  
- 读取方在确认就绪后用 **`assume_init_read()`**（unsafe，由协议保证已初始化）。

### 2.2 状态标志：`AtomicBool` + 内存序

- **`ready`**：发送方 `store(true, Release)` → 接收方 `load(Acquire)` 见消息写入。  
- **禁止** 用 Relaxed 当「数据已写好」的信使。

### 2.3 类型安全：`Sender` / `Receiver` + 消耗 `self`

- `send(self, …)`、`receive(self)` **各只能调用一次**，编译期杜绝二次 send/receive 的数据竞争。  
- 比仅靠运行时检查更可靠。

### 2.4 阻塞：`park` / `unpark`

- 接收方未就绪时 **`thread::park()`** 交出 CPU（对比第 4 章忙等自旋）。  
- 发送方 `Release` 写消息后，对登记好的接收线程 **`unpark()`**。  
- 实现见 **`5.1-one-shot-channel/5.1-one-shot-channel-demo.rs`**：接收方在 `park` 前把 `thread::current()` 写入 `receiver_thread`。

## 3. 与书中精简代码的对照

仓库实现：**`5.1-one-shot-channel/5.1-one-shot-channel-demo.rs`**（修正了「在 `split` 时捕获错误线程」的问题 — 应在 **接收方** 登记线程句柄）。

```bash
cargo build --manifest-path atomic/Cargo.toml
# study_atomic::chapter_05::demo()
```

**运行逻辑简述**

1. `split` 重置通道，得到 `Sender` / `Receiver`。  
2. 接收线程：`receive` → 登记自身 → `Acquire` 见 `ready` 为假则 `park`。  
3. 发送线程：写入 `MaybeUninit` → `Release` 置 `ready` → `unpark` 接收线程。  
4. 接收方醒来，`assume_init_read` 取走消息。

## 4. 业务落地场景

| 场景 | 技术点 |
|------|--------|
| **全局唯一 ID / 进度汇总** | `fetch_add` 或 **CAS 循环** 防溢出（`../Chapter-02-Atomics/2.4-cas/2.4-cas-id-allocator-demo.rs`） |
| **极短临界区、多核、低延迟** | 自旋锁 + `spin_loop`（`../Chapter-04-Spin-Locks/4.1-spin-lock/4.1-spin-lock-demo.rs` / `lock_cas`） |
| **单次结果回传** | One-Shot Channel + park/unpark（本章；思想同 `oneshot::channel`） |
| **临界区长或需休眠** | `Mutex` / 内核 futex，勿 CAS 空转 |

---

## 5. 面试一句话

**第五章用 `MaybeUninit` 存一条消息、`AtomicBool` 的 Release/Acquire 同步就绪、`Sender`/`Receiver` 消耗 self 保证单次收发，接收端 park、发送端 unpark，把原子与线程阻塞合成最小通道。**
