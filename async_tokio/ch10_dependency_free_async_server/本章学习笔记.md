# 第 10 章：无依赖异步服务器 (Building an Async Server with No Dependencies) —— 学习笔记

本章是全书的集大成之作。它将前面各章节的任务、执行器、唤醒器与网络等知识点汇聚在一起，引导读者**尽量只使用 Rust 标准库**（不依赖 Tokio、hyper 等第三方异步栈）从零理解「异步服务器」各部件如何拼合。

> 说明：书中完整服务器篇幅很长；本仓库用**两个标准库示例**覆盖「非阻塞 TCP + `WouldBlock`」与「`RawWaker` + 最小 `block_on` 轮询」两块核心直觉，其余请按书在独立 crate 中补全。

---

## 1. 核心目标：解密异步底层逻辑

* **拨云见日**：暂时剥开成熟运行时的封装，看清 **`poll` / `Context` / `Waker`** 与任务队列如何配合。
* **系统构成**：自定义执行器、唤醒器、I/O 与调度策略共同构成「最小运行时」。
* **适用场景**：在 niche 场景做**极轻量**或**强定制**的调度，或通过通道与 Tokio 等框架**边界协作**。

---

## 2. 唤醒器与执行器的从零实现

### 2.1 手动实现 Waker

* **`RawWaker` 与 `RawWakerVTable`**：用函数指针表描述 `clone` / `wake` / `wake_by_ref` / `drop` 行为，再 **`Waker::from_raw`** 构造 `Waker`。
* **职责**：`wake` 路径应把对应任务重新挂回就绪队列；教学版可先用**忙轮询 / yield** 代替完整就绪队列，但应清楚这与生产级 epoll/IOCP 驱动差距巨大。

### 2.2 构建执行器 (Executor)

* **任务队列**：常用 **`VecDeque`** 保存待轮询的 `Future`（多以 **`Pin<Box<dyn Future<...>>>`** 承载）。
* **轮询逻辑**：弹出任务 → 构造 **`Context`** → **`poll`**：
  * **`Ready`**：把结果写回通道/调用方并丢弃任务；
  * **`Pending`**：将任务放回队列尾部（或依赖 `Waker` 精确唤醒），进入下一轮。

---

## 3. 核心异步原语的构建

* **`TcpStream` / `TcpListener`**：
  * **`set_nonblocking(true)`** 后，`read`/`write`/`accept` 在暂不可用时返回 **`WouldBlock`**。
  * 手写 **`Future`**：遇 `WouldBlock` 时 **`Poll::Pending`** 并注册/依赖 **`Waker`**（教学版可简化为外层轮询）。
* **异步 Sleep**：用计时器 Future 返回 **`Pending`**，**不要**在异步路径上调用 **`std::thread::sleep`** 阻塞执行线程。

---

## 4. 服务器架构设计 (Server Architecture)

* **分发模型**：监听线程 accept，新连接交给工作线程 / 独立执行器实例（书中示意）。
* **并行性**：每个连接对应独立 Future 状态，可在多执行器上并行推进。
* **状态标志 (`FLAGS`)**：可用 **`AtomicBool`** 等控制 worker 休眠/唤醒，减少空转（实现细节以书为准）。

---

## 5. 项目优化与测试

### 5.1 二进制优化

在 **`Cargo.toml`** 的 **`[profile.release]`** 中可设 **`opt-level = "z"`** 等以缩小体积（按项目权衡调试性与体积）。

### 5.2 异步客户端实战

书中可用**大量并发连接**压测自研运行时；客户端若仍用 std，需注意 **`TcpStream::connect` + 非阻塞** 或自建多路复用，与服务器假设一致。

---

## 6. 常见陷阱与建议 (Gotchas)

* **效率差异**：Tokio 等利用 **epoll / kqueue / IOCP** 与成熟唤醒路径；自研忙轮询主要服务于**理解**，不默认等价于生产性能。
* **不要重造轮子**：生产默认仍选成熟运行时，自研栈会牺牲生态与久经沙场的边界处理。
* **调试**：可用小型 **`CountingFuture`** 等观察轮询次数与任务流向。

---

## 总结

第 10 章揭示：**互联网可以看作一个不太友好的超级 API**；掌握从零拼运行时的思路，有助于真正理解如何在 **I/O 边界**上「杂耍」多个任务而不白白占用 CPU（同时认清何时应交回给成熟框架）。

## 7. 配套代码说明（本仓库）

* **本目录 `ch10_std_tcp_nonblocking.rs`**：仅 **`std`**：`TcpListener::set_nonblocking` + **`WouldBlock`** 轮询 `accept`，并用短延迟线程发起一次连接。运行：`cargo run --example ch10_std_tcp_nonblocking`（在仓库根目录）。
* **本目录 `ch10_noop_waker_block_on.rs`**：仅 **`std`**：`RawWaker`/`RawWakerVTable` 构造 **no-op `Waker`** + 最小 **`block_on`** 驱动一个 `Future`（`Pending` 时 **`thread::yield_now`**，教学用）。
* **同目录 `demo.rs`**：仍为 `rustc` 占位；完整多线程执行器 + 服务器请按书逐步实现。
