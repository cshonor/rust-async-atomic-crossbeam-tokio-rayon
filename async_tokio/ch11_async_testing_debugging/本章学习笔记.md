# 第 11 章：测试 (Testing) —— 学习笔记

本章是全书的最后一章，介绍如何对复杂的异步 Rust 系统做较全面的测试。随着异步系统规模增大，测试不仅是验证功能，更是发现**死锁**、**竞态**与**背压**问题的关键手段。

---

## 1. 核心知识点与工具

### 1.1 基础异步测试

* **在同步壳里驱动异步**：可用 **`futures::executor::block_on`**、`futures_lite::future::block_on`，或在测试中 **`#[tokio::test]`** 直接 `await`。
* **Mocking（模拟）**：
  * 常用 **`mockall`** 为 trait 生成 mock 实现。
  * **AAA**：Arrange（准备）、Act（执行）、Assert（断言）。
  * 通过 **`expect_*`**、**`with`**、**`returning` / `return_once`** 等约束调用次数与参数。

> **与书中代码的对应**：若 trait 方法返回 **`impl Future<Output = ...>`**（AFIT），`mockall` 在稳定工具链上往往改为 **`async-trait`** 的 `async fn`（由 `async_trait` crate 提供），语义等价、工具支持更成熟。见本仓库 **`tests/ch11_database_mock.rs`**。

### 1.2 陷阱检测：死锁与竞态

* **死锁 (Deadlock)**：多个任务互相等待对方释放资源而永久卡住。
  * **测试思路**：用 **`tokio::time::timeout`**（或测试框架的超时）包裹可疑逻辑；超时即判定本次用例失败并辅助定位。
* **竞态 (Race)**：非原子读—改—写导致状态丢失。
  * **思路**：在高并发下重复运行（`cargo test` 多线程 + 压力循环），或对易错段使用 **`loom`** 等状态探索（进阶）。

### 1.3 网络与通道测试

* **通道背压**：在测试中压满 `mpsc`/`bounded` 容量，断言发送侧阻塞或 `try_send` 失败等符合预期。
* **HTTP Mock**：可用 **`mockito`**、`wiremock` 等模拟端点与响应序列（本仓库笔记不强制绑定具体库版本，按书与 `Cargo.lock` 选型即可）。

## 2. 细粒度的 Future 轮询测试

对底层状态机可**手动 `poll`**（配合 **`Pin`** 与 **`noop` / 自定义 `Waker`**），断言 **`Poll::Pending` / `Poll::Ready`** 的转移顺序。

* **锁与 `Pending`**：可验证在某一 `Future` 持有异步锁时，另一竞争者在未就绪时应停在 **`Pending`**（具体 API 依 `tokio::sync::Mutex` 等而定）。

## 4. 常见陷阱与建议 (Gotchas)

* **URL 硬编码**：网络测试里将 base URL 做成可注入配置，区分 mock / 本地 / 预发。
* **死锁定位**：超时能判定「卡住」，根因仍需结合栈与锁顺序分析；可缩小用例范围二分定位。
* **活锁 (Livelock)**：任务在运行却无进展；需业务层让步、随机退避或重构协议。

第 11 章为全书画上句号：异步 Rust 的测试要在**多任务、锁、网络与时序**下仍保持可预期行为，才能真正发挥「无畏并发」的工程价值。
