# 6.7 Interacting with Our Event Bus via Async Tasks

## Tokio 任务中消费事件

典型流程：

1. `let handle = bus.subscribe().await;`
2. `tokio::spawn` 循环 `while let Some(ev) = handle.next().await { ... }`
3. 任务结束或句柄 `drop` → 触发 §6.6 退订。

## 垃圾回收 (Garbage Collector) 任务

注销后队列资源不宜在热路径同步删除。书中实现**后台 GC 任务**：

- 批处理扫描「已失效订阅者 ID」；
- 从 `HashMap` 移除空队列，避免锁竞争拖慢 `publish`。

## 背压 (Backpressure)

当 **生产速率 ≫ 消费速率**：

- `VecDeque` 无限增长；
- 延迟累积、内存压力上升。

| 策略 | 说明 |
|------|------|
| 有界队列 | 满则丢弃或阻塞生产者 |
| 速率限制 | 令牌桶 / 漏桶 |
| 流控信号 | 消费者就绪后再 publish |

与 §6.8 一致：仅在确有瓶颈时引入上述复杂度。
