# 第 6 章：响应式编程 (Reactive Programming) —— 学习笔记

本章介绍了**响应式编程**范式及其在异步 Rust 中的应用。响应式编程的核心是代码能够动态地对数据值或事件的变化做出反应。

---

## 1. 核心概念：观察者模式 (Observer Pattern)

响应式系统的基础通常是观察者模式。该模式包含两个核心角色：

* **主体 (Subject)**：持有状态并在状态发生变化时发布更新。
* **观察者 (Observer)**：订阅主体的更新，并根据自身需求做出反应。
* **优点**：解耦了代码。你可以轻松增加观察者的数量，而无需修改主体的代码。

### 1.1 案例研究：加热器系统

书中通过一个简单的加热器系统来演示这一模式：

* **主体**：当前温度 (`TEMP`) 和目标温度 (`DESIRED_TEMP`)。
* **观察者**：
  * **加热器 (Heater)**：当当前温度低于目标温度时升温。
  * **显示器 (Display)**：当温度发生变化时，在终端打印当前状态。
* **技术实现**：使用 `AtomicI16`（及书中可能出现的 `AtomicBool` 等）存储共享状态，在多任务环境下用合适的 **内存序** 读取/更新。

---

## 2. 数据并发与原子操作

在响应式系统中，多个异步任务可能同时访问和修改数据。

* **快照问题**：在获取数据「快照」和执行决策（如打印显示）之间，数据可能已经被其他任务修改。
* **`compare_exchange`**：处理原子值的关键原语之一。它会检查当前值是否等于**期望值**，若是则写入新值；否则返回当前实际值。可用于实现「若仍是旧值则更新，否则重算」的乐观重试逻辑。

---

## 3. 事件总线 (Event Bus)

当系统变得复杂，需要将事件广播给多个订阅者时，**事件总线**比简单的观察者模式更有效。

### 3.1 核心组件

* **`EventBus` 结构体**：通常包含待投递/待处理事件的队列（常由 `Mutex` / 通道保护）以及订阅者标识（如递增 ID）。
* **`EventHandle`（句柄）**：订阅者通过句柄与总线交互，句柄持有订阅 ID 与对总线的引用（或 `Weak` 以避免循环引用）。

### 3.2 内存泄漏防御

如果订阅者任务被取消或句柄被丢弃，但没有显式退订，总线中的队列与映射可能持续堆积，导致**内存泄漏**。

* **解决方案**：为 `EventHandle` 实现 **`Drop`**，在句柄离开作用域时自动 `unsubscribe` / 清理队列中的该订阅者。

---

## 4. 关键挑战：背压 (Backpressure)

* **定义**：当事件产生的速率高于处理速率时，会导致事件在队列中积压。
* **应对策略**：书中常提到缓冲 (Buffering)、流控制 (Flow control)、速率限制 (Rate limiting)、负载均衡 (Load balancing) 等。

---

## 5. 示例代码：简单的回调逻辑

虽然回调是实现响应式的一种简单方式，但过度使用会导致「回调地狱」，使代码难以维护。

```rust
fn perform_operation_with_callback<F>(callback: F)
where
    F: Fn(i32),
{
    let result = 42;
    callback(result);
}

fn main() {
    let my_callback = |result: i32| {
        println!("结果是: {}", result);
    };
    perform_operation_with_callback(my_callback);
}
```

---

## 总结

第 6 章展示了如何利用 Rust 的原子类型、互斥锁和异步任务构建动态响应系统。它强调了**解耦**的重要性，并提醒开发者注意**背压**和**内存泄漏**等在大规模并发系统中常见的风险。
