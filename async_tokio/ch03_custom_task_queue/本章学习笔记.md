# 第 3 章：构建自己的异步队列 (Building Our Own Async Queues) —— 学习笔记

本章通过「动手实现」的方式，带你从底层构建一个简单的异步队列。这不仅能帮你巩固对 Task 和 Future 的理解，还能让你看清这些对象是如何在异步运行时（Runtime）中流动的。

---

## 1. 核心依赖与工具

要构建一个最小化的异步运行时，通常需要以下三个核心组件：

* **`async-task`**：核心工具，负责将 Future 包装成可执行的 Task。
* **`futures-lite`**：Future 接口的轻量级实现，提供 `block_on` 等基础功能。
* **`flume`**：高性能的**多生产者、多消费者 (MPMC)** 通道。
  * **为什么选 Flume？** 它支持接收端克隆，提供无锁算法和无界通道，非常适合高度并发的队列任务分发。

---

## 2. 任务调度原理：干洗店类比

书中用一个生动的例子解释了异步处理流程：

* **Future（标签）**：就像缝在脏大衣里的清洗说明（Future 包含如何执行计算的逻辑）。
* **Runnable（包装好的大衣）**：当你把大衣交给干洗店，店员给它套上塑料袋并贴上编号，它就变成了「可运行」的状态（Runnable 对象包含了 Future 和调度逻辑）。
* **Task（存根）**：店员给你的取衣凭证。通过这个凭证，你可以最终获取清洗好的大衣（Task handle 用于等待结果并获取 Future 的返回值）。

---

## 3. 多队列与任务窃取 (Task Stealing)

为了让运行时更高效，我们需要处理不同优先级的任务：

### 3.1 优先级队列

可以创建两个全局队列：`HIGH_QUEUE`（高优先级）和 `LOW_QUEUE`（低优先级）。

* **高优先级**：配备更多的工作线程（Worker Threads）。
* **低优先级**：配备较少的线程。

### 3.2 任务窃取算法

如果高优先级队列已空，而低优先级任务堆积如山，高优先级的线程不应闲置，而应从低优先级队列中「窃取」任务执行。

* **逻辑流程**：
  1. 检查自己的主通道。
  2. 如果为空，检查其他（低优先级）通道。
  3. 如果仍为空，线程进入「停车 (Parking)」状态，等待 100ms 后重试。
* **风险**：过度窃取可能导致轻量级的网络任务被计算密集型任务阻塞，因此需根据业务场景权衡。

---

## 4. 示例代码：自定义 `join!` 宏

为了提高人体工程学（Ergonomics），我们可以编写宏来并发处理多个 Future。

```rust
macro_rules! join {
    ($($future:expr),*) => {{
        let mut results = Vec::new();
        $(
            // 对传入的每个 Future 调用 block_on
            // 注意：这只是一个简化的同步等待演示
            results.push(futures_lite::future::block_on($future));
        )*
        // 保持结果顺序与输入顺序一致
        results
    }};
}

// 使用示例
let outcome: Vec<u32> = join!(task_one, task_two);
```

重要说明：上述宏对每个 Future **依次**调用 `block_on`，因此是**顺序执行**，并不是 Tokio `join!` 那种在同一执行器上真正交错推进的并发。要对照书中「自建队列 + 窃取」的语义，需要配合 `async-task` 与通道实现调度循环；见下文配套示例。

## 5. 常见陷阱与易错点 (Gotchas)

* **阻塞式 Sleep 的破坏力**：在异步函数中使用 `std::thread::sleep` 会直接阻塞整个执行器（Executor）线程。在演示中，这常被用来观察任务在队列中的顺序，但在生产环境中**绝对禁止**，因为它会拖慢所有任务的进度。
* **Future 的确定性**：获取锁（Mutex）的过程是不确定的，因此不能假设异步操作的结果会按特定顺序写入日志。
* **递归深度**：若用递归抓取链接且深度过大，可能触发栈溢出；异步状态机也会放大栈压力，需控制深度或改为迭代/breadth-first。
* **后台任务丢失**：若 `spawn` 出子任务却既未等待其完成，也未交给运行时明确托管，任务可能在完成前被丢弃。应保留 `JoinHandle` 并适时 `await`，或使用运行时提供的「分离运行」API（以所用 crate 文档为准；书中 `.detach()` 需对应到你选的运行时 API）。

---

## 总结

第 3 章通过手动实现 `spawn_task` 和 `Runtime` 结构，揭示了异步编程并不是魔法，而是一套**基于通道和状态机的手动调度机制**。这种底层视角对于后续理解 Tokio 等复杂框架的配置至关重要。
