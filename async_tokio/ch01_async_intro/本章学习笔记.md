# 第 1 章：异步编程入门 (Introduction to Async) —— 学习笔记

本章提供了异步编程的高层概览，探讨了为什么在现代软件开发中我们需要异步模式，以及它如何与操作系统的**进程 (Processes)**和**线程 (Threads)**相互协作。

---

## 1. 什么是异步编程？

### 1.1 背景与动因

* **硬件瓶颈**：随着摩尔定律的放缓，单纯依靠增加 CPU 核心数来获取性能提升变得越来越困难。
* **资源效率**：在微服务等系统中，存在大量的 **I/O 网络调用**。异步编程允许我们在不增加 CPU 核心的情况下，通过在单个线程上有效切换任务（利用任务等待响应的「死时间」），来更高效地利用系统资源。

### 1.2 核心定义

**异步 (Async)** 允许程序在调用某些耗时操作（如读取文件、网络请求）时继续执行其他任务，而不是挂起并导致程序无响应。

* **类比**：就像洗衣服。当你把衣服丢进洗衣机后，你不会站在旁边无所事事直到洗完，而是去处理其他家务。

---

## 2. 操作系统基础：进程与线程

为了理解异步，必须先了解它在操作系统中的位置：

### 2.1 进程 (Processes)

* **定义**：进程是操作系统分配资源的独立单位，拥有**独立的内存空间**。
* **特点**：
  * 进程之间是相互隔离的，一个进程崩溃通常不会影响其他进程。
  * **缺点**：跨进程通信 (IPC) 昂贵且复杂，创建进程的开销比线程大。
* **在异步中的地位**：标准的 Rust 异步编程通常不使用多进程，而是让异步系统运行在进程内部。

### 2.2 线程 (Threads)

* **定义**：线程是 CPU 执行的最小指令序列，由调度器管理。
* **特点**：
  * **共享内存**：同一进程内的线程共享内存空间，这使得数据共享非常容易。
  * **上下文切换**：当 CPU 从一个线程切换到另一个线程时，需要保存和恢复状态，这具有一定的计算开销。
* **与异步的关系**：异步运行时（Runtime）通常使用线程池来执行异步任务。

---

## 3. 异步的工作原理 (Mechanisms)

1. **CPU 调度**：CPU 会为线程分配时间片。当发生中断（如 I/O 到达）或线程自愿让出（Yield）时，CPU 会保存当前状态并切换任务。
2. **并发与并行**：
   * **并行 (Parallelism)**：多个任务在不同核心上同时运行。
   * **并发 (Concurrency)**：多个任务的执行相互交错（Interleaved）。
3. **非阻塞 I/O**：异步的核心在于不阻塞 CPU。通过特定的宏（如 `tokio::join!`），程序可以同时启动多个请求，总耗时仅取决于最慢的那个请求，而不是所有请求的总和。

---

## 4. 示例代码：Tokio 基础并发

以下代码演示了如何使用 Tokio 运行时并发发起多个 HTTP 请求，从而实现显著的性能提升。

```rust
use std::time::Instant;
use reqwest::Error;

#[tokio::main]
async fn main() -> Result<(), Error> {
    let url = "https://jsonplaceholder.typicode.com/posts/1";
    let start_time = Instant::now();

    // 使用 tokio::join! 并发执行 4 个请求
    // 这种方式允许请求同时进行，而不是一个接一个执行
    let (_, _, _, _) = tokio::join!(
        reqwest::get(url),
        reqwest::get(url),
        reqwest::get(url),
        reqwest::get(url),
    );

    let elapsed_time = start_time.elapsed();
    // 在测试中，这种并发方式比同步方式快了约 4.7 倍
    println!("并发请求总耗时: {} ms", elapsed_time.as_millis());

    Ok(())
}
```

## 5. 常见陷阱与注意事项 (Gotchas)

* **文件 I/O 的局限性**：在许多平台上，标准库的异步文件读取可能并不是真正的异步，而是**阻塞式**的。这是因为底层文件 API 的限制，真正的异步文件 I/O（如 Linux 上的 `io_uring`）通常需要特定的库（如 `tokio-uring`）支持。
* **不可用的加速**：异步不会加速内存中的计算，它主要用于优化处理速度远低于内存操作的 **I/O 边界任务**（如磁盘读写、网络、键盘输入）。
* **线程停车 (Thread Parking)**：当线程处于等待状态时被称为「已停车」(Parked)，意味着它被阻塞且不消耗 CPU 资源，直到被唤醒（Unparked）。
* **标准库 Sleep 的错误使用**：在异步任务中使用 `std::thread::sleep` 会阻塞整个执行线程，导致其他任务无法运行。**必须使用异步版本的 sleep**（如 `tokio::time::sleep`），它会向执行器返回 `Pending` 并让出 CPU。

---

## 总结

第 1 章强调，异步是处理**多个不需持续占用 CPU 的任务**的强大工具。它通过在单个（或少量）线程上同时「杂耍」多个操作，极大提高了系统的响应能力和资源利用率。
