# 第 1 章：异步编程入门 (Introduction to Async) —— 学习笔记

本章对应《Async Rust》**第 1 章**，按书中小节拆成模块：**1.1～1.6**。下面各节可单独复习；文末为与本仓库示例的对应关系。

---

# 第 1.1 节：什么是异步？ (What Is Async?)

### 1. 核心定义

* **并发任务处理**：异步编程允许我们在不增加 CPU 核心的情况下，通过在单个线程上「杂耍」多个任务来获得性能提升。
* **利用死时间**：它主要利用任务中的「死时间」（Dead Time），例如等待服务器响应或磁盘 I/O 的时间，在此期间让 CPU 处理其他任务。
* **生活类比**：异步就像洗衣服，你不需要在洗衣机旁死等，而是可以在洗衣服的同时去做其他家务。

### 2. 硬件背景

* **摩尔定律放缓**：随着半导体进步放缓，单纯靠增加 CPU 核心数来解决性能问题变得不再廉价。
* **资源效率**：异步通过更高效地利用系统资源（尤其是处理微服务中的大量网络调用）来应对不断增加的软件需求。

### 3. 异步的实际效果

* **示例对比**：在处理 4 个顺序 HTTP 请求时，耗时约为各请求之和（如 656ms）；而使用 `tokio::join!` 宏进行异步并发处理后，耗时仅为最慢请求的响应时间（如 137ms）。
* **性能提升**：在不增加线程数量的情况下，速度可提升数倍（示例中约为 4.7 倍；**具体数字以你本地网络与目标服务为准**）。

# 第 1.2 节：进程简介 (Introduction to Processes)

### 1. 什么是进程？

* **操作系统抽象**：进程是操作系统提供的一种抽象，由 CPU 执行。程序指令加载到内存中，由 CPU 按顺序执行。
* **隔离性**：进程拥有独立的内存空间，一个进程崩溃不会损坏另一个进程的内存，具有极强的故障隔离能力。

### 2. 进程与并发的关系

* **多进程模型**：例如 PostgreSQL 数据库为每个连接生成一个单独的进程。这种模型简单，不需要复杂的锁机制。
* **缺点**：生成进程非常昂贵且难以扩展；一旦核心数用尽，新进程就会被阻塞。
* **通信成本**：进程间通信（IPC）涉及昂贵的序列化开销。

### 3. 在 Rust 中的视角

* 虽然可以通过多进程实现异步行为（如同时运行多个二进制连接程序），但在 Rust 中，由于语言本身的内存安全特性，多进程提供的隔离优势不如在 C/C++ 中那么显著（Rust 更常在线程 + async 单进程内解决并发）。

# 第 1.3 节：什么是线程？ (What Are Threads?)

### 1. 核心定义

* **最小执行单位**：线程是 CPU 执行的最小指令序列，由调度器独立管理。
* **内存共享**：一个进程内的多个线程共享同一块内存空间，这使得线程间的数据交换非常容易。

### 2. 线程与异步任务的区别

* **执行方式**：线程可以在不同的 CPU 核心上同时运行（并行）；而异步任务通常是在单个线程内轮流使用 CPU（并发）。
* **管理机制**：线程由 OS 调度，而异步运行时（Runtime）通常使用**线程池**执行异步任务，从而在少量 OS 线程上「 multiplex 」大量任务。

### 3. 线程间协作原语

* **`JoinHandle`**：允许程序等待某个线程完成。
* **`Condvar`（条件变量）**：允许线程进入休眠，并在收到特定通知时被唤醒。多个线程可以订阅同一个 `Condvar`。
* **`AtomicBool` 与 `Mutex`**：用于在多线程环境下安全地共享和修改状态。

# 第 1.4 节：异步的应用场景 (Where Can We Utilize Async?)

### 1. 识别瓶颈

* **计算速度差异**：CPU 和内存的操作通常以**纳秒（ns）**计（如访问 RAM 约 100ns）；而 I/O 操作（写硬盘、发网络请求）通常以**毫秒（ms）**计。
* **时间鸿沟**：在打开一个文件的时间内，CPU 可以执行数百万次操作。因此，I/O 往往是程序的性能瓶颈。

### 2. 核心价值

* 异步允许程序在调用耗时操作时继续执行，而不是挂起并导致程序无响应。
* **主要用处**：
  * 文件系统 I/O 调用。
  * 网络请求（API 获取、数据库操作）。
  * 接收外部输入（鼠标、键盘）。

# 第 1.5 节：使用异步进行文件 I/O (Using Async for File I/O)

### 1. 异步文件操作的现状

* **非真正的加速**：异步并不会直接加快文件读取速度，因为速度受限于磁盘性能而非 CPU。
* **防止阻塞**：其真正意义在于，在文件读取或写入期间，程序可以继续运行其他逻辑而不被阻塞。

### 2. 实现机制

* **OS 限制**：标准的异步文件读取有时在底层仍是阻塞的，这取决于 OS 的 API 支持（例如，Linux 5.10+ 的 `io_uring` 可以实现真正的异步 I/O；Tokio 生态中有 `tokio-uring` 等专门路径）。
* **代码示例逻辑（书中思路）**：使用 **`tokio::fs::File`** 打开文件，并配合 **`tokio::sync::watch`** 通道监控文件元数据（Metadata）的变化。

### 3. 关键点：异步 Sleep

* 在异步循环中检查文件变化时，必须使用 **`tokio::time::sleep`**，而非 **`std::thread::sleep`**。后者会阻塞整个执行线程；前者将任务交还给执行器，让出 CPU。

# 第 1.6 节：利用异步提升 HTTP 请求性能 (Improving HTTP Request Performance)

### 1. 网络延迟的特性

* 网络请求是异步的绝佳用例，因为发送请求到接收响应之间存在明显的网络延迟。在此期间 CPU 往往是空闲的。

### 2. 并发请求模型

* **非阻塞获取**：异步函数（如 `fetch_data`）以非阻塞方式执行。例如发起一个需要 5 秒才能响应的请求，程序可以立即执行下一个任务（如计算用户登录时间）。
* **乱序完成**：由于任务是并发执行的，耗时短的任务（1 秒）会比耗时长但先启动的任务（5 秒）更早完成并打印结果。

### 3. 工具与工具链

* **Tokio**：提供异步运行时的抽象。
* **Reqwest**：支持异步 HTTP 请求的库。
* **`tokio::join!`**：用于同时运行多个 Future，总耗时由最慢的那个 Future 决定。

### 4. 书内示例：`tokio::join!` + `reqwest`

```rust
use std::time::Instant;
use reqwest::Error;

#[tokio::main]
async fn main() -> Result<(), Error> {
    let url = "https://jsonplaceholder.typicode.com/posts/1";
    let start_time = Instant::now();

    let (_, _, _, _) = tokio::join!(
        reqwest::get(url),
        reqwest::get(url),
        reqwest::get(url),
        reqwest::get(url),
    );

    println!("并发请求总耗时: {} ms", start_time.elapsed().as_millis());
    Ok(())
}
```

## 易错点备忘（贯穿全章）

* **文件 I/O**：许多平台上「异步文件」仍可能阻塞底层线程；真异步需看 OS 与运行时能力。
* **异步不加速纯计算**：收益在 **I/O 边界**。
* **`std::thread::sleep` 禁止出现在 async 热路径**：改用 `tokio::time::sleep` 等。

---

## 章节小结

第 1 章强调：异步适合**多个不持续占用 CPU、但常等待 I/O** 的任务；通过运行时调度与 **`join!`** 等组合，在少量线程上提高吞吐与响应性。
