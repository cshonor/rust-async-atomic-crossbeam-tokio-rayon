# 第 2 章：异步 Rust 核心概念 —— 深度解析版

本章是所有异步编程的**骨架**：若你理解编译器为 `async fn` 生成了什么、以及 **`await` 为何不占用线程干等**，后面章节会顺很多。

与 Python / Go 等「自带大块运行时、约定俗成即可开写」不同，Rust 更强调你理解两件事：**任务/Future 在内存里如何被固定与驱动**，以及 **OS 或运行时如何在 I/O 就绪时把你唤醒再继续 `poll`**。本章的「三驾马车」是：**`Future`（状态机 + `poll`）**、**`Pin`（防自引用被移动）**、**`Waker`（就绪通知）**；它们通常由 **`Task` + `Executor`** 串起来使用。

---

## 1. 异步任务的骨架：`Future` Trait

在 Rust 里，异步操作的结果类型是 **`Future`**：不是「立刻的值」，而是一个**尚未完成的工作**，完成后产出 `Output`。

### 1.1 为什么是「轮询（Polling）」而不是回调满天飞？

许多语言用回调；回调在运行时往往伴随额外分配与生命周期管理。Rust 把异步编译成 **`Future` 状态机**（一个结构体，字段里保存跨 `await` 的局部状态），配合 **`poll`**，更贴近 **零成本抽象**：热路径上不必为「每个回调节点」都付出同等动态开销（具体仍取决于你怎么组合 `async`/动态分发）。

### 1.2 `poll` 的细节：它本身是同步的

`Future` 的核心是：

```rust
fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
```

* **`Poll::Ready(T)`**：这一步已经算出结果，可以结束。
* **`Poll::Pending`**：这一步还不能完成（例如在等网卡数据）。执行器**不会**让 OS 线程在这里空转傻等；它会把这个任务先放下，去 **`poll` 队列里的别的任务**。  
  因此 **`await` 不阻塞线程**的直观理解是：**线程仍在跑，只是在多个任务之间切换 `poll` 与推进**（真正「睡觉」的是任务状态机，不是傻占着 CPU 自旋——配合 `Waker` 后更是如此）。

---

## 2. 内存安全的核心：固定 (Pinning)

新手常见困惑：为什么和 `async` 绑在一起的类型总跟 **`Pin`** 打交道？

### 2.1 自引用结构体的陷阱

`async fn` 展开后，跨 `await` 的局部变量会进入编译器生成的状态机字段。若某字段**指向同结构体中的另一字段**，就形成**自引用**。

* Rust 里值可能被**移动**（传参、`Vec` 重分配等）。
* 若带自引用的状态机被移动，内部指针仍指向**旧地址** → **未定义行为（UB）**（实践中常表现为崩溃或诡异数据）。

### 2.2 `Pin<P>` 与 `Unpin`

* **`Pin<&mut T>`**（在 `Future` 上常见）：约定在 `poll` 期间**不能安全地移动 `T` 本身**（从而保护自引用字段的地址稳定）。  
* **`Unpin`**：多数标量、`String` 等**没有**自引用需求，自动 `Unpin`，在 `Pin` 里仍可用 **`get_mut()`** 等安全路径改字段（本笔记中的 `CounterFuture` 即此类教学例子）。

---

## 3. 协作式调度：`Context` 与 `Waker`

若任务返回 **`Pending`**，执行器不能靠「每隔 1µs 轮询一次」来猜何时就绪——那是忙等，浪费 CPU。

### 3.1 `Waker` 做什么？

`Waker` 是**通知句柄**，典型流程：

1. `Future` 在 `poll` 里发现还缺数据，返回 **`Pending`**。
2. 从 **`Context`** 里取得 **`Waker`**，交给 OS / 运行时 / 驱动（例如：「套接字可读时，请调用 `wake`/`wake_by_ref`」）。
3. 事件就绪后调用 **`wake`**，执行器把对应 **`Task`** 重新放入就绪队列，稍后再次 **`poll`**。

### 3.2 与「停车 / 让出 CPU」的关系

有了基于事件的唤醒，工作线程可以在没有就绪任务时**阻塞在 epoll/IOCP 等**上，而不是空转；这与「在 `Pending` 上自旋忙等」完全不同。教学用 **`wake_by_ref()` 立刻再调度** 与真实 I/O 路径不同，仅用于理解控制流。

## 4. 实战：手动实现一个计数 `Future`

下面与 **`ch02_counter_future.rs`**（本目录；与根目录 `cargo run --example ch02_counter_future` 对应）一致。注意：在 **`Pin<&mut Self>`** 里改字段，应通过 **`self.get_mut()`**（本例 `CounterFuture` 为 **`Unpin`**，无自引用，这样写最清晰）。

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

struct CounterFuture {
    count: u32,
}

impl Future for CounterFuture {
    type Output = u32;

    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output> {
        let this = self.get_mut();
        this.count += 1;
        println!("正在轮询，当前计数: {}", this.count);

        if this.count < 5 {
            cx.waker().wake_by_ref();
            Poll::Pending
        } else {
            Poll::Ready(this.count)
        }
    }
}

#[tokio::main]
async fn main() {
    let my_future = CounterFuture { count: 0 };
    let result = my_future.await;
    println!("最终结果: {}", result);
}
```

**说明**：`wake_by_ref()` 在这里是**立刻请求再次调度**的教学技巧；真实网络栈里，由内核/运行时在**就绪点**调用 `wake`。若手写 **`RawWaker` / `RawWakerVTable`**，属于更底层细节，可对照第 10 章与 `std::task` 文档继续下钻。

## 5. 常见陷阱（新手必看）

1. **不要在异步任务里用 `std::thread::sleep`**  
   它会阻塞**整个 OS 线程**；该线程上若还跑着别的任务，会一起被拖死。请用 **`tokio::time::sleep`**（或当前运行时提供的异步睡眠）。

2. **`std::sync::Mutex` 与 `.await` 的组合**  
   在 **`async fn` 里持着 `std::sync::MutexGuard` 再过 `.await`** 非常危险：`.await` 可能让出到运行时，**锁仍未释放**，其他任务若也要同一把锁，易造成**死锁或长时间停顿**。更稳妥的是 **`tokio::sync::Mutex`**，或缩小临界区、在 `.await` 前 **`drop(guard)`**。  
   另：在 **`poll` 里**一般**不要**去「阻塞式等锁」——`poll` 应快速返回 `Pending`/`Ready`；需要异步互斥时，用运行时提供的原语，而不是在 `poll` 里卡死。

3. **`Future` 是惰性的**  
   只调用 `async fn` 而不 **`await`** / 不交给执行器 **`poll`**，很多情况下**不会真正执行**体内逻辑；只是构造了状态机。

4. **取消安全 (Cancel Safety)**  
   使用 **`select!`**、超时丢弃分支时，要确认被取消的 `Future` 不会留下半初始化状态（未释放资源、半写事务等）。

5. **`poll` 里与 `Mutex` 的笔记**  
   若在**手写 `poll`** 的路径里需要同步原语，优先保证**不阻塞**；Tokio 的异步锁不能在 **`poll` 里 `await`**——`poll` 本身不能是 `async`。

---

## 6. 章节小结

异步 Rust 的脉络可以概括为：**`Task` 包装并驱动 `Future`（状态机）**；**`Executor`** 负责 **`poll` 与排队**；**`Waker`** 把 **「I/O 就绪」** 转成 **「再次 `poll`」**；**`Pin`** 保护 **「自引用状态机不被非法移动」**。四者加上 OS 事件源，才构成完整图景。
