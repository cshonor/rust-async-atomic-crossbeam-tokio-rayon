# 第 2 章：异步 Rust 核心概念 (Basic Async Rust) —— 学习笔记

本章深入探讨了异步 Rust 的底层构建模块。理解这些概念是掌握异步编程从「会写语法」到「理解原理」的关键跨越。

---

## 1. 核心定义：任务 (Tasks) 与 Future

### 1.1 什么是任务 (Task)？

* **定义**：任务是一个异步计算或操作，由**执行器 (Executor)** 管理并驱动至完成。
* **特征**：它代表了一个 Future 的执行过程，可能包含多个组合或链接在一起的 Future。

### 1.2 什么是 Future？

* **定义**：Future 是一个占位符，代表一个可能尚未完成的计算的值。
* **核心地位**：它是异步计算的基石。在 Rust 中，Future 是通过 `Future` trait 实现的。

---

## 2. Future 的运行机制：轮询 (Polling)

Future 本身是**被动**的。它不会自动运行，必须由执行器不断地调用其 `poll` 方法。

* **`poll` 方法**：接收一个自身的可变引用和上下文 `Context`。
* **返回值 (`Poll<T>`)**：
  * **`Poll::Ready(result)`**：计算完成，返回结果。执行器随后可以释放资源。
  * **`Poll::Pending`**：计算尚未完成。
* **非异步的 `poll`**：`poll` 函数本身不是 `async` 的。如果 `poll` 是异步的，会导致循环依赖，因为你需要轮询一个 Future 来解析另一个正在被轮询的 Future。

---

## 3. 内存布局的关键：固定 (Pinning)

在异步编程中，Future 经常包含指向自身的引用（自引用结构）。

* **原理**：Rust 编译器经常在内存中移动值（如函数传参、集合扩容）。
* **风险**：如果一个自引用结构被移动，其内部指针将指向错误的内存地址，导致未定义行为。
* **解决方案 (`Pin`)**：通过将 Future 包装在 `Pin` 中，我们向编译器保证该对象在内存中的地址将被**固定**，永远不会再移动。
* **`Unpin` Trait**：大多数基本类型（数字、字符串等）都实现了 `Unpin`，意味着它们可以安全地移动。

---

## 4. 协作的关键：上下文 (Context) 与 唤醒器 (Waker)

为了避免执行器无效地反复轮询那些尚未就绪的任务（忙等待），Rust 使用了唤醒机制。

* **上下文 (`Context`)**：目前的主要作用是提供对 **Waker** 的访问。
* **唤醒器 (`Waker`)**：这是一个句柄，用于通知执行器某个特定任务已准备好继续运行。
* **流程**：
  1. Future 在 `poll` 时发现未就绪，返回 `Pending`。
  2. Future 将 `Waker` 注册到某个事件源（如计时器或网络套接字）。
  3. 当外部事件发生时，调用 `waker.wake()`。
  4. 执行器收到信号，将该任务放回运行队列，准备再次轮询。

---

## 5. 示例代码：构建一个简单的计数 Future

以下代码展示了如何手动实现 `Future` trait。

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

struct CounterFuture {
    count: u32,
}

impl Future for CounterFuture {
    type Output = u32;

    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output> {
        let this = self.get_mut();
        this.count += 1;
        println!("正在轮询，当前计数: {}", this.count);

        if this.count < 5 {
            cx.waker().wake_by_ref();
            Poll::Pending
        } else {
            Poll::Ready(this.count)
        }
    }
}

#[tokio::main]
async fn main() {
    let my_future = CounterFuture { count: 0 };
    let result = my_future.await;
    println!("最终结果: {}", result);
}
```

说明：`poll` 内使用 `get_mut()` 是因为 `self` 的类型为 `Pin<&mut Self>`；本例中 `CounterFuture` 为 `Unpin`，字段未形成自引用，这样写最清晰。`wake_by_ref()` 仅作教学演示（立即再次调度）；真实 I/O 应在就绪时由内核/运行时调用 `wake`。

---

## 6. 常见陷阱与注意事项 (Gotchas)

* **取消安全 (Cancel Safety)**：当使用 `tokio::select!` 或超时操作时，Future 可能会在完成前被取消。必须确保取消操作不会导致系统进入错误状态（如锁未释放、文件未关闭）。
* **互斥锁的选择**：在 Future 的 `poll` 函数内部，应使用标准库的 `std::sync::Mutex` 而非 Tokio 的异步 Mutex，因为 `poll` 不允许异步等待。
* **数据共享**：在 Future 之间共享状态通常需要组合使用 `Arc` 和 `Mutex`。
* **远程唤醒**：对于网络调用，不应持续轮询套接字，而应通过保存 Future 的 Waker，在 OS 发出数据到达信号时再唤醒 Future。
