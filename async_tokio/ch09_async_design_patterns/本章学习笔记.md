# 第 9 章：设计模式 (Design Patterns) —— 学习笔记

本章介绍了在异步系统中常用的一些设计模式。通过**隔离的模块化**并组合不同模式，可以把异步能力渐进式接入既有同步代码，同时提升可维护性与容错。

---

## 1. 构建隔离模块 (Building an Isolated Module)

本模式通过**同步外观（Facade）**对外暴露能力，在模块内部运行异步运行时。

* **工作流**：调用方调用**阻塞式** API（如提交任务并拿到 ID），内部在后台 `spawn`；需要结果时再阻塞 `join`/轮询映射表直到完成。
* **实现要点**：模块内封装 **Runtime**、**JoinHandle / ID 映射**、通道等；对外隐藏 `async`，从而**缩小**异步对遗留同步代码的侵入面（代价：阻塞线程、错误与取消语义要设计清楚）。

---

## 2. 核心异步模式详解

### 2.1 瀑布模式 (Waterfall / 管道式链)

* **定义**：一串异步步骤，**上一步的输出**作为**下一步的输入**顺序衔接（与责任链「沿链传递」思想相近，但异步里常表现为连续的 `await` / `and_then` 风格组合）。
* **在 Rust 中**：可用 **`?`** 串联 `Result`，失败时提前返回，保持路径简洁。

### 2.2 装饰器模式 (Decorator)

* **定义**：在不改变被包装对象 API 的前提下，为其附加横切能力（日志、指标、超时等）。
* **异步形态**：例如包装一个 **`Future`**，在 `poll` 前后打点；若手写 `poll`，常涉及 **`Pin`** 投影——要么 **`unsafe`** 做投影，要么用 **`Box::pin`** / 组合子库降低手写 `poll` 的频率。

### 2.3 状态机模式 (State Machine)

* **场景**：任务在后台根据当前状态切换行为（如 On/Off、阶段枚举）。
* **削峰**：当队列深度或并发超阈值时切换状态，**拒绝或延迟**接纳新工作，实现简单流控。

### 2.4 重试模式 (Retry)

* **逻辑**：调用失败时按策略重试（网络抖动、503、锁竞争等）。
* **退避 (Backoff)**：在重试间隔加入递增延迟（常见指数退避 + 抖动），避免对故障方「疯狂重试」造成二次伤害。

### 2.5 熔断模式 (Circuit Breaker)

* **定义**：根据失败率/连续失败次数在 **Closed / Open / Half-Open** 等状态间切换。
* **Open 时**：快速失败，避免把资源持续砸向已不健康依赖；待冷却后再探测恢复。

---

## 3. 示例代码：重试模式逻辑

以下展示将重试与指数退避融入异步任务（书中常用 `sleep` 倍增；生产环境应加**抖动**与**总超时**）。

```rust
use std::time::Duration;

use tokio::time::sleep;

async fn do_something() -> Result<(), String> {
    for i in 0..5 {
        match perform_async_call().await {
            Ok(_) => return Ok(()),
            Err(e) => {
                println!("发生错误: {}，正在重试...", e);
                sleep(Duration::from_secs(1 << i)).await;
            }
        }
    }
    Err("重试次数耗尽".to_string())
}
```

---

## 总结

第 9 章说明：用**隔离模块**降低接入成本，用**瀑布/装饰器/状态机**组织控制流，用**重试 + 退避**与**熔断**保护下游。把「能跑」提升为「**在生产负载下仍可预期地失败与恢复**」。
