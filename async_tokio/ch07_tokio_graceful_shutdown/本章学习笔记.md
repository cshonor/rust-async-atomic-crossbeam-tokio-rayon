# 第 7 章：定制化 Tokio (Customizing Tokio) —— 学习笔记

本章深入探讨了如何超越 Tokio 的默认配置，通过**定制化运行时 (Runtime)** 和使用**本地池 (Local Pools)** 来获得对异步任务处理的精细控制。这对于需要高性能、特定线程绑定或复杂生命周期管理的应用至关重要。

---

## 1. 核心知识点与原理

### 1.1 定制化运行时 (Building a Runtime)

Tokio 不仅仅是一个宏 (`#[tokio::main]`)，它提供了 **`runtime::Builder`**（常用入口如 **`Builder::new_multi_thread()`**）来微调行为：

* **线程管理**：可配置 **`max_blocking_threads`** 等，防止大量 `spawn_blocking` 耗尽系统资源。
* **监控钩子**：通过 **`on_thread_start`** / **`on_thread_stop`** 在工作线程启动或停止时回调，便于接入指标与日志。
* **阻塞线程生命周期**：阻塞线程池的**闲置保留时间**等在不同 Tokio 版本上 API 名称可能调整（请以当前版本的 `runtime::Builder` 文档为准）。

### 1.2 本地池与任务固定 (Local Pools & Pinning)

在标准的多线程 Tokio 运行时中，工作窃取有助于均衡负载，但也会带来同步与缓存行为上的不确定性。

* **`tokio-util` 库**：提供 **`LocalPoolHandle`**，为每个工作线程维护独立的 **`LocalSet`**，从而承载 **`!Send`** 的 Future。
* **`spawn_pinned` / `spawn_pinned_by_idx`**：把任务固定到某一工作线程上执行。
* **性能与语义**：固定后可安全使用 **`Rc`**、**线程局部 (`thread_local!`)** 等「不能跨线程发送」的状态，减少跨线程锁竞争（仍需自行保证不阻塞 worker）。

### 1.3 线程局部状态提取 (Extracting State)

本章还涉及从各工作线程汇总统计的高级用法（例如通过 **`spawn_pinned_by_idx`** 在每个索引上跑提取任务，再用 **`HashMap`** 汇总）。具体数据结构以书中实现为准。

---

## 2. 核心架构：Local Pool 布局

与第 3 章「自建运行时」相比，**本地池**是在 **Tokio 生态内**做「线程亲和 + `!Send` 任务」的折中方案：

* **隔离性**：可为不同优先级准备不同池或不同 `Runtime`，避免工作线程互相窃取不符合你预期的任务。
* **确定性**：任务绑定到特定 worker 后，对线程局部与缓存局部性更可控；代价是**不做窃取**，可能出现单线程过载（见 §5）。

---

## 3. 示例代码：使用本地池固定任务

以下代码演示如何使用 **`tokio_util::task::LocalPoolHandle`**，并用 **`spawn_pinned_by_idx`** 把任务放到指定 worker（索引从 0 开始，且须 `< pool.num_threads()`）。

```rust
use tokio_util::task::LocalPoolHandle;

#[tokio::main]
async fn main() {
    let pool = LocalPoolHandle::new(4);

    let handle = pool.spawn_pinned_by_idx(
        || async {
            println!("任务正在线程 0 上运行");
            42
        },
        0,
    );

    let result = handle.await.unwrap();
    println!("最终结果: {}", result);
}
```

## 4. 进阶：优雅停机 (Graceful Shutdowns)

在异步系统中，直接强制退出可能导致数据丢失或状态不一致。

* **信号监听**：使用 **`tokio::signal::ctrl_c()`**（以及平台相关的 `unix::Signal` 等）捕获退出指令。
* **清理逻辑**：在收到停止信号后，依次 **`await`** 尚未完成的句柄、刷盘/关连接，再退出进程；书中若提到 `get_complete_count` 一类统计，可作为「收尾前最后一次汇总」的示例接口名。

---

## 5. 常见陷阱与注意事项 (Gotchas)

* **`UnsafeCell` 的风险**：若用 **`UnsafeCell`** 绕过 `RefCell` 的检查，必须保证数据**不会被发送到其他线程**且访问发生在固定线程上；与 **`spawn_pinned`** 语义结合时仍要自行证明无数据竞争，否则为 **UB**。
* **阻塞任务限制**：即使使用 **`spawn_blocking`**，也应配合 **`max_blocking_threads`** 与业务限流，否则仍可能拖垮整体延迟。
* **本地池的局限**：本地池不做任务窃取；若某一 worker 任务极重而其他 worker 空闲，会出现**负载不均**，需架构上规避或拆池。

---

## 总结

第 7 章是通往异步 Rust 高手的必经之路。它揭示了 Tokio 并不是一个黑盒：通过 **`tokio-util`** 的本地池与 **`runtime::Builder`**，可以针对**低延迟、线程敏感**或**分线程统计**等场景做针对性优化。
