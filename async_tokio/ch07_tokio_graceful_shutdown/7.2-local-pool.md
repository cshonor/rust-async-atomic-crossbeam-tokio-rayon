## 2. 核心架构：Local Pool 布局

与第 3 章「自建运行时」相比，**本地池**是在 **Tokio 生态内**做「线程亲和 + `!Send` 任务」的折中方案：

* **隔离性**：可为不同优先级准备不同池或不同 `Runtime`，避免工作线程互相窃取不符合你预期的任务。
* **确定性**：任务绑定到特定 worker 后，对线程局部与缓存局部性更可控；代价是**不做窃取**，可能出现单线程过载（见 §5）。

---

## 3. 示例代码：使用本地池固定任务

以下代码演示如何使用 **`tokio_util::task::LocalPoolHandle`**，并用 **`spawn_pinned_by_idx`** 把任务放到指定 worker（索引从 0 开始，且须 `< pool.num_threads()`）。

```rust
use tokio_util::task::LocalPoolHandle;

#[tokio::main]
async fn main() {
    let pool = LocalPoolHandle::new(4);

    let handle = pool.spawn_pinned_by_idx(
        || async {
            println!("任务正在线程 0 上运行");
            42
        },
        0,
    );

    let result = handle.await.unwrap();
    println!("最终结果: {}", result);
}
```
